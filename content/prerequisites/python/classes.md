>
> - **类（Class）**与**对象（Object）**：图纸与产品的关系

## 生活场景切入

P5 的函数解决了「动作复用」。但现实世界的东西往往是**数据 + 动作**的绑定体。

一台自动售货机：

- 它**有**：库存、价格表、钱箱（数据）
- 它**会**：出货、找零、报警（动作）

你不需要知道内部机械怎么转，只要会按按钮。而且全城同一型号的售货机，按钮用法一模一样——**先造一批机器，再让用户按按钮**，这就是面向对象的全部直觉。

```text
类 Class      = 图纸 / 型号     （定义：售货机长什么样、会干什么）
对象 Object   = 按图纸造出的机器 （实例：你面前这台具体的机器）
```

## 核心概念拆解

### 概念 1：定义一个最小的类

```python
class Student:                       # 约定：类名首字母大写
    def __init__(self, name, age):   # 出厂设置（构造函数）
        self.name = name             # 挂在 self 上的 = 这台机器自己的属性
        self.age = age

    def introduce(self):             # 方法：这台机器会的动作
        return f"我是{self.name}，今年{self.age}岁"

# 图纸画好了，开始造！
stu1 = Student("小明", 16)     # 对象 1
stu2 = Student("小红", 17)     # 对象 2——同一个类，各自的数据互不干扰

print(stu1.introduce())       # 我是小明，今年16岁
print(stu2.introduce())       # 我是小红，今年17岁
```

三个新面孔，一次认完：

| 新面孔             | 是什么                                                              |
| ------------------ | ------------------------------------------------------------------- |
| `__init__`         | 「出厂程序」：每次造新对象时自动运行一遍，负责装上初始零件          |
| `self`             | 「这台机器自己」：方法被调用时，Python 自动把对象本身塞进第一个参数 |
| `stu1.introduce()` | 调用语法：**名词点动词**——「 stu1 的 introduce 动作」               |

### 概念 2：属性与方法——「有什么」和「会什么」

```text
对象 stu1
├── 属性（名词）：name = "小明"   age = 16      ← 用 stu1.name 访问
└── 方法（动词）：introduce( )                  ← 用 stu1.introduce() 调用
```

判断窍门：**带括号的是方法（要干活），不带括号的是属性（直接取）**。属性也可以随时改：`stu1.age = 18` 过完生日改一下就行。

### 概念 3：AI 代码里的「名词.动词」

现在你能读懂真实 PyTorch 代码的句式了：

```python
model = NeuralNetwork()          # 按图纸造一个模型对象
model.train()                    # 喊它进入训练模式（方法）
output = model(images)           # 喊它处理一批图片（方法）
optimizer.zero_grad()            # 清空优化器里存的旧梯度（方法）
loss.backward()                  # 让损失反向传播（方法）
scheduler.step()                 # 优化器走一步（方法）
```

每一行都是「某台机器的某个动作」。框架作者用类把成百上千的相关数据和函数打包成几个名字，使用者只需记住「哪台机器会哪个动作」。**这就是为什么 P6 排在 NumPy 前面——不认识「名词.动词」，下一课的 `arr.mean()` 就读不懂了**。

### 概念 4：NumPy 数组也是对象（剧透）

```python
import numpy as np

arr = np.array([1, 2, 3, 4])   # 造一个数组对象
print(arr.mean())              # 2.5  ← 数组自带的求平均方法
print(arr.max())               # 4    ← 自带的求最大方法
```

`arr.mean()` 读作「arr 的 mean 方法」——数组这个对象出厂就自带一堆统计动作。对比 P5 里我们自己写的 `average(nums)` 函数写法：功能相同，但「动作挂在数据身上」后，代码读起来更接近自然语言。这是下节课的主旋律。

## 本章英文小词典

| 英文                     | 中文      | 一句话记忆                           |
| ------------------------ | --------- | ------------------------------------ |
| Class                    | 类        | 图纸、型号                           |
| Object / Instance        | 对象/实例 | 按图纸造出的具体机器                 |
| Attribute / Property     | 属性      | 对象「有什么」（数据成员）           |
| Method                   | 方法      | 对象「会做什么」，调用时要加括号     |
| Constructor (`__init__`) | 构造函数  | 造对象时的出厂程序                   |
| Encapsulation            | 封装      | 内部细节藏起来，只露按钮——售货机原理 |
| Dot notation             | 点号语法  | `obj.method()` = 名词.动词()         |
| Self                     | 自身      | 方法里的第一个参数，「这台机器自己」 |

## 自测一下

> [!question]- 1. `stu1.name` 和 `stu1.introduce()` 的本质区别是什么？
> 前者取**属性**（存好的数据，直接读出来），后者调**方法**（执行一段动作，可能现场计算）。判断口诀：有括号是在「喊它干活」，没括号是在「翻它的口袋」。`stu1.introduce`（忘写括号）不会报错，只会拿到「方法本身」这个奇怪的东西——又一个静默坑。

> [!question]- 2. `__init__` 里的 `self.name = name` 两边都叫 name，它们是一个东西吗？
> 不是！`self.name` 是**对象的属性**（挂在这台机器身上的永久零件）；右边的 `name` 是**参数**（造机器时递进来的临时原料）。这句的意思：「把我收到的原料 name，安装成这台机器的 name 属性」。左边属于对象、右边属于本次调用——用同一个词只是习惯性重名。

> [!question]- 3. 看到 `loss.backward()`，用本课语言完整解读这行代码。
> `loss` 是一个对象（由损失函数计算返回），`backward` 是它自带的方法，括号表示「现在就执行」。整行 = 「喊 loss 这台机器执行它的 backward 动作」——内部实现是复杂的反向传播运算，但使用者不需要知道，这正是封装的价值。能说出「对象 + 方法 + 封装」这三个词，本课就算过关。

> [!question]- 4. 为什么说「两个 Student 对象的数据互不干扰」？这对训练多个模型意味着什么？
> 因为每个对象有自己的独立属性空间：`stu1.name` 改了不影响 `stu2.name`。同理，你可以用同一个网络类造出 model_a 和 model_b 两个模型实例，分别用不同超参数训练，它们的权重各自演化、互不污染——做对比实验就是这么干的。「一份图纸，N 台独立机器」是工程实验的基本姿势。
