## 生活场景切入

NumPy 很强，但它是「裸表格」：只有数字位置，没有名字。现实中的数据长这样：

| 姓名 | 年龄 | 城市 | 成绩 |
| ---- | ---- | ---- | ---- |
| 小明 | 16   | 北京 | 88   |

每一列有**名字**，每一行是一个**样本**——Excel 表、数据库表、CSV 文件全是这个长相。处理这种「带标签的表格」，Python 的答案是 **Pandas**。AI 工程里流传一句话：

> 「一个 AI 项目，80% 的时间在用 Pandas 清洗数据，20% 才在训练模型。」

会了它，你就承包了项目的绝大部分工时 😄。

## 核心概念拆解

### 概念 1：DataFrame 与 Series

```python
import pandas as pd

df = pd.DataFrame({
    "姓名": ["小明", "小红", "小刚", "小美"],
    "年龄": [16, 17, 16, 18],
    "成绩": [88, 45, 92, 60],
})
print(df)
```

输出（自动排版成表）：

```text
   姓名  年龄  成绩
0  小明  16    88
1  小红  17    45
2  小刚  16    92
3  小美  18    60
```

- **DataFrame（数据框）**：整张表。左边那列 `0 1 2 3` 是**索引（Index）**——每行的行号
- **Series（系列）**：单独一列（含索引），可以理解为「带名字的一维数组」

`df["成绩"]` 取出一列 Series；`df["成绩"].mean()` 直接得平均分 `71.25`。P6 的对象思维再次生效：**方法全挂在对象身上**。

### 概念 2：拿到新数据的「体检三步」

任何真实项目第一步都是搞清楚手里是什么货色：

```python
df = pd.read_csv("students.csv")     # ① 读文件（还有 read_excel / read_json）

print(df.head())          # ② 头几行长什么样？
print(df.info())          # 每列类型、有没有缺失
print(df.describe())      # 数字列的统计摘要：平均、最大最小、四分位

print(df.shape)           # (行数, 列数) —— 和 NumPy 同款
```

> [!tip] 为什么先体检再动手？
> 真实数据一定有惊喜：年龄列里混着「未知」，成绩列有空值 NaN，某列被误读成文字……先 `info()` + `describe()` 扫一遍，比直接上手建模省掉后面十倍的返工。这也是审查 AI 生成的分析报告时最该问的：「你看过原始数据吗？」

### 概念 3：选行挑列——两种坐标系统

```python
# 挑列：方括号 + 列名
scores = df["成绩"]              # 一列 → Series
two_cols = df[["姓名", "成绩"]]  # 多列要传列表 → 还是 DataFrame

# 按位置取行：iloc（index location）
first_row = df.iloc[0]           # 第 0 行（下标从 0 开始的老朋友）

# 布尔过滤：最有用的一招！
failed = df[df["成绩"] < 60]         # 所有不及格的行
beijing = df[df["城市"] == "北京"]   # 所有北京的行
adults  = df[(df["年龄"] >= 18) & (df["成绩"] > 80)]   # 组合条件
```

最后一行的组合规则：条件之间用 `&`（且）、`|`（或），**每个条件必须各自套括号**——忘括号是 Pandas 新手第一坑。

还记得 P7 的 `arr[arr > 80]` 吗？布尔过滤完全同源：**True 的留下、False 的丢弃**。学会一次，两库通吃。

### 概念 4：改数据与存回去

```python
df["及格"] = df["成绩"] >= 60        # 整列新增一列布尔值
df.loc[df["成绩"] < 60, "成绩"] = df["成绩"] * 1.5   # 定位改数：补考加成？

df.to_csv("students_cleaned.csv", index=False)       # 存回文件
```

「读入 → 体检 → 过滤/加工 → 存出」，这四个动作就是数据清洗的完整闭环。你在 P10 实战里会把这套流程走一遍真的。

## 自测一下

> [!question]- 1. `df[df["成绩"] < 60]` 里出现了两个方括号，各自的职责是什么？
> 内层 `df["成绩"]` 先取出成绩这一列 Series；`< 60` 把它变成 True/False 的布尔 Series；外层方括号拿这个布尔序列当面具，只保留 True 对应的行。三层连起来读：「把成绩小于 60 的那些**行**给我」。Pandas 大量语法都是这种「由内向外」的洋葱结构，读不懂时一层层剥开就好。

> [!question]- 2. `df.iloc[0]` 和 `df["姓名"]` 返回的类型一样吗？
> 不一样。`df.iloc[0]` 取第 0 **行**，返回 Series（这一行各列的值）；`df["姓名"]` 取**列**，也返回 Series——但方向不同。想取一个格子（第 0 行的姓名）：`df.iloc[0]["姓名"]` 或更快 `df.loc[0, "姓名"]`。「行用 iloc/loc，列用名字」是最不容易混的分工记忆法。

> [!question]- 3. 为什么 `(A) & (B)` 必须加括号？不加会发生什么？
> 因为 Python 运算符优先级里比较/按位运算的顺序问题：`df["a"] >= 18 & df["b"] > 80` 会先把 `18 & df["b"]` 当成一个整体去算（& 比 >= 优先级高），直接报错或者给出诡异结果。规则很简单：**每个条件自己一套括号，永不吃亏**。

> [!question]- 4. 「80% 时间洗数据」这句话对 AI 项目意味着什么？
> 至少三点：① 学习重心要匹配——Pandas 熟练度直接决定干活效率；② 模型效果上限常由数据质量决定（垃圾进垃圾出），与其狂调参不如回头查数据；③ 审视任何 AI 结论时先问数据处理过程：缺失值怎么处理的？异常值剔除了吗？样本筛选有没有偏差？——数据环节的水分，往往比模型环节多得多。
