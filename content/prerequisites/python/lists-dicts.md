## 生活场景切入

上一课的变量盒子有个致命弱点：**一个盒子只能装一个东西**。

现在要记录全班 40 个同学的 AI 测验成绩，难道要写 `score_1 = 88`、`score_2 = 92`……写到第 40 行？要是换成全国高考成绩，几百万个变量？

现实中的收纳早就解决了这个问题：

| 现实收纳                   | Python 容器          |
| -------------------------- | -------------------- |
| 一排编号的储物柜           | **列表 List**        |
| 贴了标签的药盒（早/中/晚） | **字典 Dictionary**  |
| 柜子里又套小盒子           | 嵌套（列表里放列表） |

机器学习的数据几乎都住在这两种容器里：**数据集是列表，每条样本的特征是字典**。学会它们，你就看懂了 AI 代码的一半。

## 核心概念拆解

### 概念 1：列表 = 编号储物柜

```python
scores = [88, 92, 75, 60, 95]     # 方括号 + 逗号分隔
print(scores[0])                   # 88   ← 第 1 个
print(scores[3])                   # 60   ← 第 4 个
print(len(scores))                 # 5    ← 一共有几个
```

最反直觉的一点来了：

> [!important] 下标从 0 开始！
> 第 1 个元素的编号是 `[0]`，不是 `[1]`。`scores[3]` 取的是**第 4 个**元素。
>
> 为什么？可以理解为「离起点偏移了几步」：第 1 个元素偏移 0 步，第 4 个偏移 3 步。全世界的编程语言几乎都这么设计，吐槽无效，习惯就好 😄

列表的常用操作一览：

```python
scores.append(83)      # 往末尾添加一个
scores[0] = 90         # 改第 1 个
del scores[2]          # 删掉第 3 个
scores.sort()          # 从小到大排序
max(scores)            # 最大值   min(scores) 最小值
sum(scores) / len(scores)   # 平均分！（求和 ÷ 个数）
```

最后那行值得多看一眼：**求平均 = sum 除以 len**。以后你训练模型时看到的「平均损失」，本质就是这个算式。

### 概念 2：字典 = 标签药盒

列表靠位置找东西，字典靠**标签**找东西：

```python
student = {"name": "小明", "age": 16, "passed": True}
print(student["name"])        # 小明
student["age"] = 17           # 生日过了，改标签里的内容
student["city"] = "北京"      # 新增一个标签
```

结构拆开看：每一项都是 **键（Key）: 值（Value）** 的配对。

```text
"name"  → "小明"     键是文字标签，值可以是任何类型
"age"   → 16
```

什么时候用哪个？一句话：**顺序有意义用列表，名字有意义用字典**。

### 概念 3：嵌套——真实数据的模样

把字典装进列表，就是一张「表格」——机器学习数据集的标准长相：

```python
dataset = [
    {"面积": 55,  "房间": 2, "价格": 300},   # ← 第 0 条样本
    {"面积": 80,  "房间": 3, "价格": 450},
    {"面积": 120, "房间": 4, "价格": 700},
]

print(dataset[1]["面积"])      # 80 —— 第 1 条样本的「面积」特征
print(dataset[2]["价格"])      # 700
```

读法从外往内：`dataset[1]` 先取出第 1 条（是个字典），再 `["面积"]` 从字典里取标签对应的值。**以后你在 Pandas（P8）里处理的每一张表，本质都是这个结构**。

### 概念 4：切片——一次拿一段

列表还支持「切香肠」式取值：

```python
nums = [10, 20, 30, 40, 50, 60]
print(nums[1:4])     # [20, 30, 40]  ← 从下标 1 到 3（4 不包含！）
print(nums[:3])      # [10, 20, 30]  ← 前 3 个
print(nums[-1])      # 60            ← 负数从末尾倒数
```

`[1:4]` 不包含 4 这件事又是一个经典坑。记忆口诀：**左含右不含**。

## 本章英文小词典

| 英文                 | 中文        | 一句话记忆                            |
| -------------------- | ----------- | ------------------------------------- |
| List                 | 列表        | 有序、可修改的元素序列                |
| Element / Item       | 元素        | 容器里的每一个成员                    |
| Index (复数 indices) | 下标/索引   | 编号，**从 0 开始**                   |
| Key / Value          | 键 / 值     | 字典的标签和标签里的东西              |
| Append               | 追加        | 在列表末尾加一个                      |
| Slice                | 切片        | 一次取出一段（左含右不含）            |
| Nested               | 嵌套        | 容器里套容器                          |
| Length               | 长度        | 元素个数，用 `len()` 获得             |
| Mutable / Immutable  | 可变/不可变 | 列表可变；字符串不可变（改它=造新的） |

## 自测一下

> [!question]- 1. `colors = ["红", "绿", "蓝"]`，`colors[1]` 和 `colors[-1]` 分别是什么？
> `colors[1]` 是 `"绿"`——下标 1 对应第 2 个元素（0 开始！）；`colors[-1]` 是 `"蓝"`——负下标从末尾倒数，-1 就是最后一个。这两个知识点合起来考过无数初学者。

> [!question]- 2. `nums = [5, 3, 8, 1]`，执行 `nums.sort()` 后再 `print(nums)` 输出什么？如果想要的是 `[5, 3, 8, 1]` 排好序的新列表但不想动原列表呢？
> 输出 `[1, 3, 5, 8]`。注意 `.sort()` 是**原地修改**，原列表没了！想保留原列表要用 `sorted(nums)`——它返回排好的新列表，原列表保持不动。这种「就地改 vs 返回新」的双轨设计在 Python 里到处都是，遇到时先问一句：它会改我的原件吗？

> [!question]- 3. 为什么说 `dataset[1]["面积"]` 这种「列表套字典」的结构是机器学习数据的原型？
> 拆开看正好对应两个概念：**行**与**列**——列表的下标定位「第几条样本」（行），字典的键定位「哪个特征」（列）。Excel 表、Pandas 的 DataFrame、PyTorch 的 Dataset，全是这个逻辑在不同规模下的化身。理解了这个嵌套，后面学 P7/P8 时会不断产生「原来是它！」的既视感。

> [!question]- 4. `prices = [30, 25, 40]`，写出求平均价格的代码，并说出每一步的类型。
> `sum(prices) / len(prices)` → `95 / 3` → `31.666...`。`sum()` 返回 int，`len()` 返回 int，但 `/` 除法在 Python 里永远返回 float——所以结果是浮点数 `31.666666666666668`。顺带一个坑：Python 还有 `//` 整除运算符（丢掉小数部分），别混用。
