>
> - **方程（Equation）**：天平两端的平衡游戏，解方程就是保持平衡地挪东西
> - 一元一次方程 → 一元二次方程：求根公式与判别式
> - **配方法**：把任何二次式变回完全平方式的魔术（M7 会再遇到它）

> - AI 视角：训练的「停止条件」就是一个不等式

## 生活场景切入

妈妈说：「我买的苹果数量是你的 3 倍，我比你多 12 个，你买了几个？」

你心里立刻开始倒推：多出来的 12 个正好是「2 份」，所以一份是 6 个。恭喜——你刚刚心算了一个方程：

```text
设我买 x 个：   3x − x = 12   →   2x = 12   →   x = 6
```

**正向计算**是拿着数字算答案；**解方程**是拿着答案反推数字。AI 训练本质上是后一种：我们不知道模型的参数应该是多少，但知道「好的参数应该让误差小」——于是列方程（损失函数），解出参数（梯度下降）。

## 核心概念拆解

### 概念 1：方程 = 天平

方程就是一架平衡的天平：等号左右两边重量相等。

```text
    x + 3
  ─────────●─────────
   ▓▓▓▓▓      10
```

解方程只有一条黄金法则：

> **对天平两边做同样的事，天平依然平衡。**

```text
x + 3 = 10
两边同时减 3：        x + 3 − 3 = 10 − 3
化简：                x = 7        ✓ 解出来了
```

移项的「变号」其实是同一条法则的速记：把 +3 挪到右边，等于两边同时减 3。

```python
# 用 Python 验证（学过 P 板块的读者可跑）
x = 7
print(x + 3 == 10)   # True —— x=7 确实是解
```

### 概念 2：一元二次方程 —— 求根公式登场

含 `x²` 的方程叫一元二次方程，标准形状：

```text
ax² + bx + c = 0        （a ≠ 0）
```

**第一步永远是配方**——把左边的 `x` 部分挤进一个完全平方：

```text
例：x² + 6x + 5 = 0

① 把常数挪走：            x² + 6x = −5
② 补上 (6/2)² = 9：       x² + 6x + 9 = 4     ← 两边同时加 9，天平不破
③ 左边正是完全平方：      (x + 3)² = 4
④ 开方（正负都要）：      x + 3 = ±2
⑤ 得两根：                x = −1 或 x = −5
```

对一般情况重复这套动作，就得到**求根公式（Quadratic Formula）**：

```text
x = (−b ± √(b² − 4ac)) / 2a
```

不用背推导，但要会**用**。验证一下刚才的例子：a=1, b=6, c=5 →

```text
x = (−6 ± √(36−20)) / 2 = (−6 ± 4) / 2 → x = −1 或 −5 ✓
```

### 概念 3：判别式 —— 根的「体检报告」

根号里的 `Δ = b² − 4ac` 叫**判别式（Discriminant）**，它决定方程有几个实数解：

| Δ 的值 | 含义                       | 例子               |
| ------ | -------------------------- | ------------------ |
| Δ > 0  | 两个不同的实数根           | `x²+x−6=0`（Δ=25） |
| Δ = 0  | 一个重根                   | `x²−4x+4=0`（Δ=0） |
| Δ < 0  | 没有实数根（图像不碰横轴） | `x²+2x+5=0`(Δ=−16) |

```python
import math

def solve_quadratic(a, b, c):
    disc = b*b - 4*a*c
    if disc < 0:
        return "无实数根"
    if disc == 0:
        return (-b / (2*a),)
    r = math.sqrt(disc)
    return ((-b + r)/(2*a), (-b - r)/(2*a))

print(solve_quadratic(1, -5, 6))   # (3.0, 2.0)
print(solve_quadratic(1, -4, 4))   # (2.0,)          重根
print(solve_quadratic(1, 2, 5))    # 无实数根
```

**人话**：把 y = ax²+bx+c 的图像画出来，「根」就是曲线穿过横轴的位置。Δ 是曲线和地面关系的三种可能：穿过去两次、擦一下、够不着。

### 概念 4：不等式 —— 带方向的约束

不等式符号回顾：

```text
>   大于          ≥  大于等于
<   小于          ≤  小于等于
```

解法和解方程几乎一样，**唯一的新规则**：

> [!warning] 两边乘除负数时，不等号必须翻转！
>
> ```text
> −2x > 6
> 两边 ÷ (−2)：  x < −3      ← 方向翻了
> ```
>
> 为什么？在数轴上想：`−2x > 6` 表示「x 越负越好」。除以 −2 相当于把整条数轴镜像翻转，左右互换。

**AI 视角**：训练循环里的「早停（early stopping）」就是一个不等式——当验证集损失连续几轮不再低于当前最优（`loss ≥ best_loss`），就停下来防止过拟合。部署时的硬性要求也是不等式：响应延迟 ≤ 100ms、内存占用 < 8GB。**方程找的是点，不等式圈的是范围；现实工程问题大多活在范围里。**

### 概念 5：二分法 —— 当公式不存在时（选读）

不是所有方程都有漂亮公式。比如 `x³ = 10`——三次、四次方程有（很复杂的）公式，五次以上被伽罗瓦理论证明根本不存在通用公式。怎么办？

**二分法（Bisection）**：只利用「连续函数会过零点」这一事实，像猜价格一样夹逼：

```text
已知 2³ = 8 太小，3³ = 27 太大 → 解在 (2, 3)
取中间 2.5³ = 15.6 太大 → 解在 (2, 2.5)
取中间 2.25³ = 11.4 太大 → 解在 (2, 2.25)
……每次区间减半，10 步后精确到小数点后三位
```

这就是**数值方法**的思想：不求精确解，求「足够接近」的解。M7 的梯度下降正是它的亲戚——不直接解出最优参数，而是一步步逼近。

## 自测一下

> [!question]- 1. 解方程：`3(x − 2) = x + 8`
> 去括号：`3x − 6 = x + 8`。
> 移项合并：`3x − x = 8 + 6` → `2x = 14` → **x = 7**。
> 验算：左边 3×(7−2)=15，右边 7+8=15 ✓。（养成验算习惯，考试和写代码都受益。）

> [!question]- 2. 方程 `x² − 4x + m = 0` 有两个相等的实数根，m 是多少？
> 「两个相等的实数根」即重根，判别式为零：
> `Δ = 16 − 4m = 0` → **m = 4**。
> 此时方程为 `(x−2)² = 0`，根 x = 2。反过来读：看到完全平方式 `(x−a)²` 就该条件反射 Δ=0。

> [!question]- 3. 解不等式并把解画在数轴上：`5 − 3x ≥ 20`
> 移项：`−3x ≥ 15`。两边除以 **−3（翻转！）**：**x ≤ −5**。
> 数轴上 −5 及其左侧全部涂黑，−5 处画实心点（因为带等号）。最容易丢分的就是忘记翻转——检查方法：代一个解进去试，如 x=−6：5−3×(−6)=23≥20 ✓；若误写成 x≥−5，代 x=0 得 5≥20 显然荒谬。

> [!question]- 4. 用二分法的思路回答：√50 介于哪两个整数之间？再精确到一位小数。
> 7² = 49 < 50，8² = 64 > 50，所以 √50 在 **7 和 8 之间**。
> 取中点 7.5² = 56.25 > 50 → 在 7 与 7.5 之间；取 7.25² ≈ 52.56 > 50 → 在 7 与 7.25 之间；取 7.1² = 50.41 略大；7.05² ≈ 49.70 略小 → √50 ≈ **7.07…**（保留一位小数为 7.1）。
> 这道题不需要背任何公式——二分法只需要「平方后会变大」这一个常识。
