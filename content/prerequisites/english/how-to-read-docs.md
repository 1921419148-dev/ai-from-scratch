> [!abstract] 本课将学到
>
> - **读英文教程 ≠ 读英文课文**：目标是获取信息，不是做阅读理解题
> - 三遍阅读法：先看结构 → 再抓重点 → 最后按需精读
> - 什么该查词典、什么可以放过，以及哪些翻译工具真的好用
> - 官方文档（docs）的常见版式：看懂一次，以后所有文档都眼熟

## 生活场景切入

你打开 PyTorch 的英文教程，第一屏是这样的：

> _Prerequisites: basic familiarity with Python. We assume you have installed PyTorch. If not, follow the installation guide._

三个长句里夹着 Prerequisites 这种大词，你的第一反应可能是：先去背单词。**方向反了**。

想想你读中文说明书的方式：你不会逐字读完电饭煲说明书，你是**带着问题翻**的——「怎么煮饭？」「那个键是干嘛的？」读英文文档也一样：它是工具书，不是课文。策略对了，词汇量要求能直接砍掉一半。

## 核心概念拆解

### 策略一：三遍阅读法

```text
第 1 遍（30 秒）  只看骨架：标题、代码块、加粗字
        ↓ 判断：这篇文章有没有我要的答案？
第 2 遍（3 分钟） 顺着骨架读段落首句
        ↓ 标记：哪一段是我真正需要的？
第 3 遍（按需）   只精读标记过的段落 + 对照代码
```

为什么有效？因为技术文章有个「良心结构」：**最重要的信息一定在标题和段首**。工程师写文档也怕读者走丢，所以把路标铺得很密——你要做的是顺着路标走，而不是把每寸草地都踩一遍。

### 策略二：代码是最好的「双语对照教材」

教程里的代码块是**不需要英语就能读懂的部分**：

```python
# Split the dataset into training and test sets
X_train, X_test, y_train, y_test = train_test_split(X, y)
```

就算完全不看注释，`train_test_split` 这个函数名已经把意思说清楚了——这正是 [[prerequisites/english/word-roots|E1]] 讲过的构词法在工程界的活用法：**程序员起名 = 词根拼接**。所以：

- 先读代码，再回头看注释和正文
- 正文看不懂时，把代码跑起来看输出，往往秒懂

### 策略三：查词要「分级处理」

不是每个生词都值得查。遇到生词先问一句：**它影响我完成任务吗？**

| 类型                 | 例子                                      | 处理方式                                        |
| -------------------- | ----------------------------------------- | ----------------------------------------------- |
| 术语（影响理解）     | gradient、epoch                           | 必须搞懂 → 查本站 [[appendix/glossary\|术语表]] |
| 动作词（影响操作）   | install、run、restart                     | 认识常见的十几个就够                            |
| 装饰性副词（不影响） | simply、obviously、nicely                 | **直接跳过**                                    |
| 作者吐槽（不影响）   | "this took me way too long to figure out" | 微笑略过                                        |

> [!important] 一个残酷但 liberating（解放性的）事实
> 技术文档里 80% 的句子是「礼貌填充」：解释你已经懂的事、道歉、开玩笑。**真正的信息密度集中在代码块、表格和列表里**。学会只吃有营养的部分。

### 策略四：认识官方文档的固定版式

几乎所有项目的官方文档（documentation，简称 docs）都用同一套版式，认一次受用终身：

| 版式记号              | 长相         | 含义                                  | 该怎么办                    |
| --------------------- | ------------ | ------------------------------------- | --------------------------- |
| **Prerequisites**     | 开头的列表   | 做之前需要什么                        | 缺啥补啥，别硬上            |
| **Note**              | Note / 📝 框 | 补充说明                              | 扫一眼即可                  |
| **Warning / Caution** | ⚠️ 框        | 这么做会出事                          | **必读**                    |
| **Installation**      | 命令行块     | 怎么装                                | 直接复制粘贴执行            |
| **Quickstart**        | 快速上手页   | 10 分钟跑通最小例子                   | 新手永远从这里开始          |
| **API Reference**     | 函数签名表   | 每个函数的参数和返回值                | 当字典用，不通读            |
| **Tutorial vs Guide** | 两类页面     | Tutorial 手把手教学；Guide 按主题查阅 | 学用 Tutorial，干活用 Guide |

### 策略五：让工具干粗活，但不外包理解

翻译工具的正确用法：

```text
整段机翻 → 快速判断这段要不要细读   ✓ 推荐用于「筛选」
关键指令逐句机翻后直接照做           ✗ 危险！术语译错会翻车
术语对照本站 glossary 双向确认       ✓ 最可靠
浏览器自带「划词翻译」               ✓ 平衡效率与准确
```

> [!warning] 机翻最容易翻车的地方
> 英文一词多义在技术语境里特别致命：_invoke_ 是「调用」不是「祈求」，_train_ 在 AI 里几乎永远是「训练」不是火车，_token_ 是「词元」不是代币礼券。**机器不知道你在 AI 语境里**，所以涉及操作的句子，最后必须由你自己用 E1/E2 的术语知识把关。

## 数学在哪里？

这一课没有计算，但有一个可以量化的账：假设一篇教程 1000 词，其中：

```text
代码块与命令     ~300 词 → 不需要英语
重复出现的术语    ~200 词 → E1+E2 已覆盖
礼貌填充与过渡    ~350 词 → 跳过不读
真正的新信息      ~150 词 → 三遍法的第 3 遍才碰
```

需要「真·英语阅读能力」的部分只剩 15%。**这就是为什么策略比词汇量重要**。

## 本章英文小词典

| 英文                 | 中文     | 一句话记忆                                   |
| -------------------- | -------- | -------------------------------------------- |
| Documentation (docs) | 文档     | 项目自带的说明书                             |
| Tutorial             | 教程     | 手把手带你的入门篇                           |
| Guide                | 指南     | 按主题查阅的工具书                           |
| Quickstart           | 快速开始 | 10 分钟最小可运行示例                        |
| API Reference        | API 参考 | 函数字典，当词典查                           |
| Prerequisite         | 前置条件 | pre 提前 + requisite 需要 → 动手前必备的东西 |
| Installation         | 安装     | install 装 + ation 名词尾                    |
| Invoke               | 调用     | in 里 + voke 叫 → 把功能叫出来干活           |
| Deprecated           | 已弃用   | de 向下 + prec 价值 → 官方不再推荐、随时会删 |
| Workaround           | 应变方法 | 绕过 bug 的临时办法                          |

## 自测一下

> [!question]- 1. 打开一份新框架的英文文档，第一步应该找哪个页面？
> **Quickstart（快速开始）**。它用最短路径带你跑通第一个例子，让你建立整体感觉；直接扎进 API Reference 或高级 Guide 很容易被细节淹没。顺序应该是：Quickstart → 跟着官方 Tutorial 做一遍 → 之后才把 Guide 和 Reference 当字典用。

> [!question]- 2. 正文读到 "Simply restart the kernel and rerun the notebook."，其中 Simply 和 and 后面那半句需要查词典吗？
> 不需要。Simply 属于「装饰性副词」，删掉不影响任何信息；后半句的 rerun = re(再) + run(运行)，用 E1 的构词法直接猜出「重新运行」。整句核心信息只有两个动作：restart the kernel（重启内核）+ rerun（重跑）。三秒钟处理完毕。

> [!question]- 3. 文档某处出现 ⚠️ Warning："This will delete all your data." 你可以跳过吗？
> 绝对不行。Note 可以扫一眼跳过，但 **Warning/Caution 框是文档作者在喊「前面有坑」**，通常涉及不可逆操作（删数据、覆盖文件、产生费用）。这恰好也是宪章精神在阅读上的体现——高风险信息永远优先。

> [!question]- 4. 为什么「整段机翻后照着做」比「划词翻译」更危险？
> 因为机器翻译不理解**技术语境**，一词多义容易译错（如 invoke、train、token），而「整段照做」意味着你没有人工校验环节，译错就直接执行错了操作。划词翻译至少强迫你逐词确认关键术语。正确姿势：机翻用来**筛选信息**，涉及操作的句子用术语知识**亲自把关**。
