## 生活场景切入

问 ChatGPT：「我们公司年假的计算规则是什么？」

它要么承认不知道，要么——更糟——**一本正经地编造一条看起来合理的假规则**（G2 的幻觉机制）。

问题不在模型笨，在于这个知识根本不在它的训练数据里。你考试遇到没复习的题怎么办？**翻书**。

RAG（Retrieval-Augmented Generation，检索增强生成）就是给模型配一个自动翻书的外挂：

```text
提问 → 先从你的资料库里检索最相关的几段 → 连同问题一起塞给模型 → 有据可依地回答
```

一句话定位：**RAG = 把模型的封闭书本考试改成开卷考试。**

## 核心概念拆解

### 概念 1：三大痛点，一剂对症

| 痛点                     | RAG 的解法                       |
| ------------------------ | -------------------------------- |
| 私有知识（模型没学过）   | 你的文档库实时供给               |
| 时效性（训练截止后的事） | 检索最新文档，无需重训           |
| 幻觉（编造事实）         | 「仅根据以下资料回答」+ 引用可溯 |

对比另一个选项——微调（DL10）：微调能教风格与格式，但**往参数里灌事实知识既贵又不可靠**（容易过拟合、更新要重训、还可能被后续训练覆盖）。事实类知识的标准答案就是外挂检索：**知识放外面，能力在里面**。

### 概念 2：离线流水线 —— 把资料库变成可检索的向量

```text
① 切片 Chunking：长文档切成 200~500 token 的小段
   （太长稀释相关性，太短丢上下文——切片策略是 RAG 第一坑）
② 嵌入 Embedding：每段过一个嵌入模型 → 一条几百维向量
③ 入库 Indexing：全部向量存入向量数据库，建相似度索引
```

嵌入模型（BERT 后代，NLP6）把「意思相近的文字」映射到相近的向量位置——这是 NLP2 词向量思想的段落级放大版。

### 概念 3：在线流程 —— 玩具实测

用户提问时（实际运行结果）：

```python
docs = {
    "doc1": "本站课程 M7 讲梯度下降，是训练神经网络的核心算法",
    "doc2": "Python 板块包含 NumPy Pandas Matplotlib 三件套",
    "doc3": "青年大学习板块整理每期主题与题目答案",
}
query = "梯度下降是什么？"

# 字符级词袋模拟 embedding，余弦相似度排序
检索排序: [('doc1', 0.334), ('doc2', 0.0), ('doc3', 0.0)]
→ doc1 精准命中，其余零分排除 ✓

# 拼装最终提示词：
背景资料：本站课程 M7 讲梯度下降，是训练神经网络的核心算法
问题：梯度下降是什么？
请仅根据背景资料回答。
```

三步走完：查询向量化 → 库内找 top-k 相似片段 → 拼进提示词交给大模型。「仅根据背景资料」这句约束是压幻觉的关键咒语——给了资料源之后，模型的注意力被锚定在真实文本上。

### 概念 4：进阶技巧速览 —— 从玩具到生产

生产级 RAG 在玩具流程上叠四层功夫：

```text
① 混合检索：向量相似 + 关键词匹配双路召回再融合
   （向量擅长语义，关键词擅长专有名词/编号——互补）
② 重排序 Rerank：粗召回 top-50 → 精排模型挑出 top-3
   （初筛快而糙，精排慢而准，两级火箭）
③ 查询改写：把口语化提问改写成检索友好的形式，
   多轮对话还要补全指代（「那第二个呢？」→ 完整问题）
④ 引用溯源：输出标注「本回答依据 doc1 第 2 段」，可点击核查
```

评估 RAG 系统也有专属指标：检索命中率（该找到的找到没）、忠实度（回答是否忠于资料而非自由发挥）——ML9 的评估纪律在 RAG 场景的特化版。

### 概念 5：RAG vs 微调 —— 决策表

| 需求                 | 选 RAG          | 选微调      |
| -------------------- | --------------- | ----------- |
| 知识频繁更新         | ✅ 改文档即生效 | ❌ 要重训   |
| 需要引用出处         | ✅ 天然可溯     | ❌ 无法溯源 |
| 教特定风格/语气/格式 | ⚠️ 提示词勉强   | ✅ 主场     |
| 教新的任务模式       | ❌              | ✅          |
| 起步成本             | 低（无训练）    | 中高        |

口诀：**事实知识用 RAG 外挂，行为模式用微调内修**。两者不互斥——成熟产品常常 RAG 供事实 + 轻微调定风格。

## 自测一下

> [!question]- 1. 为什么「往微调里灌事实」不如 RAG 可靠？至少两条理由。
> ① **更新成本**：事实会过期（价格、政策、人员），RAG 改文档秒生效，微调要重训且旧知识残留干扰；
> ② **可靠性**：微调灌入的事实以统计方式存在，模型可能在压力下仍倾向预训练知识或产生混合版本；RAG 的知识明晃晃摆在上下文里，且可附引用供人工核验。
> 补充：③ 微调无法区分「重要事实」和「噪声」——它均匀吸收一切，包括错误。业界共识已收敛于「知识外置、能力内置」。

> [!question]- 2. 切片太小会丢上下文，太大稀释相关性——给出一个你认为合理的切片策略并说明理由。
> 参考方案（言之成理即可）：**按结构切 + 重叠窗口**。优先沿标题/段落边界切（尊重文档自身的语义单元），目标 300~400 token；相邻片段保留 10~20% 重叠，防止关键句恰好被切断。
> 进阶补充：表格/代码块保持完整不切；对超长主题可用「父子索引」——检索命中子段后返回其父段落提供完整语境。
> 核心原则：**切片单位 = 检索单位 = 语义自足单元**，三者对齐是质量的关键。

> [!question]- 3. 用户问「那个东西怎么弄来着？」——纯向量检索为什么大概率失败？给出两种修复手段。
> 失败原因：口语指代（「那个东西」）缺乏实义信息，其向量与任何具体文档都不相似——检索器需要的是自足的问题描述。
> 修复：① **多轮查询改写**：让 LLM 结合对话历史把指代展开为完整问题（历史里提过「报销流程」→ 改写为「报销流程怎么操作」）；② **混合检索兜底**：加一路关键词检索，若历史中出现过独特名词可直接命中。
> 这道题揭示 RAG 在真实产品里的隐藏复杂度：**对话式检索的前处理往往比检索本身更费工**。

> [!question]- 4. 设计你们公司「员工手册问答机器人」的完整 RAG 方案，含评估计划。
> 方案骨架：
> 数据层——手册切片（按章节结构+重叠窗口）入向量库；制度类文档额外维护版本号；
> 检索层——混合检索（向量+关键词）top-20 → rerank 精选 top-3；
> 生成层——系统提示限定「仅根据资料回答，资料不含的信息明确说不知道」+ 强制引用来源；
> 评估计划——① 构建金标问答集（HR 确认的 50 个典型问题及标准答案出处）；② 检索命中率（top-3 是否包含正确段落）；③ 忠实度抽检（回答是否超出资料范围）；④ 上线后低置信回答转人工并回流测试集。
> 思想迁移检查：这套「金标准+分层指标+回流闭环」正是 ML9/DL12 实验纪律的产品版。
