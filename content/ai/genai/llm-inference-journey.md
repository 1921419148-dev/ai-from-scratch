## 生活场景切入

你在对话框输入「法国的首都是哪里？」按下回车。0.8 秒后，「法**国**的首都是**巴黎**」开始逐字浮现。

这 0.8 秒里，你的问题穿越了九个站点、上千亿参数、几十层 Transformer。这一课是全站的**总装车间**——DL 和 NLP 板块的每个零件都造好了，现在把它们装上流水线，看一台完整的发动机点火。

> [!tip] 阅读姿势
> 每一站的标题后面标了出处课程。任何一站觉得陌生，点回去补 10 分钟即可——这条流水线就是你的知识体检表。

## 第 1 站：分词 Tokenization 📍NLP1

```text
输入：「法国的首都是哪里？」
切分：[法][国][的][首][都][是][哪][里][？]
      → 每个 token 查词表转成编号 → [3256, 1177, 5, 892, ...]
```

注意「首都」被拆成了两个 token——BPE 只认高频零件，不认词语边界。这个细节埋下伏笔：模型眼里的世界是 token 序列，「词」只是人类的错觉。

## 第 2~3 站：嵌入与位置编码 📍DL9 / M5

每个 token 编号查嵌入表变成一个几千维向量；再叠加正弦位置编码，让模型知道谁在前谁在后。

```text
[法] → [0.21, -0.87, ..., 0.03]   ← 几千维
       + PE(位置1)                  ← sin/cos 波纹盖上时间戳
```

此刻，「法国的首都是哪里」已经从文字变成了**一队带位置标签的语义向量**。

## 第 4 站：96 层 Transformer Block 📍DL8/DL9

向量队列进入 GPT-3 级别的架构：96 层 block 反复加工。

每一层的内部两道工序：

```text
自注意力：每个 token 环顾四周，收集相关者的信息
   「都」这个 token 会高强度关注「首都」「法国」
   —— 因果掩码保证它只准往回看

前馈网络：每个 token 独立过 FFN 深度加工
   —— 这里存储着事实知识：「法国的首都=巴黎」就刻在某几层的某些神经元里
```

信息逐层抽象：浅层处理语法关系（「的」连接定语），深层承载语义与事实。走到第 96 层出口时，最后一个 token「里」的输出向量已经浓缩了「读完全句后的整体理解」。

## 第 5 站：输出分布 📍DL6/NLP7

最后位置的向量经输出层（与嵌入表共享权重的巨大矩阵）映射成 **15 万维的 logits**，softmax 归一化：

```text
P(巴黎)   = 0.62    ← 最高
P(法国)   = 0.11    ← 复读也合理
P(首都)   = 0.04
P(伦敦)   = 0.00001 ← 训练语料里偶尔出现的干扰项
...剩余 15 万分之其余概率
```

## 第 6 站：采样 📍NLP7 temperature

按 API 设定的温度从分布中抽签。T=0 时永远选「巴黎」；T=0.7 时 38% 的概率会抽到别的词再自我修正。**同一个问题两次回答不同——不是随机数坏了，是采样机制本来如此**。

采出的 token「巴黎」拼回输入序列，回到第 4 站继续下一轮——这就是 NLP7 的自回归循环，每吐一个字跑一遍网络。

## 第 7 站：KV Cache —— 工程师的聪明 📍G2 延伸

朴素实现有个灾难：序列每加一个 token，前面所有 token 的注意力要重算一遍——生成 1000 字就是 O(n²) 级重复劳动。

**KV Cache** 的解法：每层算过的 Key/Value 向量缓存起来不删，新 token 只需计算自己的 Q 与全体缓存的 K/V 相乘。

```text
无缓存：第 n 个 token 需要 n² 次注意力运算
有缓存：增量只需 n 次，历史 K/V 直接查表
代价：显存占用随对话长度线性增长
     （这也是长上下文贵且慢的另一重原因）
```

## 第 8 站：并行解码的真相 —— 为什么不是一个字一个字算的

GPU 的强项是批量并行。真实推理服务会把**多个用户的请求拼成 batch** 同时前向传播——你的「巴黎」和别人的「2024」在同一块显卡的不同通道里同时出生。

这解释了三个产品现象：

```text
① 高峰期响应变慢：batch 排队
② 流式输出按 token 计费而非按时间：成本由算力决定
③ 「独享实例」卖得贵：你的请求不与别人混批
```

## 第 9 站：终止与返回

采样到结束符（EOS token）或达到 max_tokens 上限，循环停止。流式接口在每个 token 出生时立刻推送给你——打字机效果的真相是一条 WebSocket 长连接上的持续推送。

## 性能指标速查 —— 读产品文档必备

| 指标       | 全称                  | 含义                          | 好坏判断                 |
| ---------- | --------------------- | ----------------------------- | ------------------------ |
| TTFT       | Time To First Token   | 按下回车到第一个字的延迟      | 由 prefill 长度+排队决定 |
| TPOT       | Time Per Output Token | 之后每个字的间隔              | 决定「打字机速度」       |
| Throughput | 吞吐量                | 整个系统每秒产出的总 token 数 | 服务商的成本核心         |

**人话总结**：TTFT 影响体感「反应快不快」，TPOT 影响「打字快不快」，Throughput 决定「这家公司赚不赚钱」。

## 自测一下

> [!question]- 1. 为什么「巴黎」这个词的概率不是 100%？什么场景下你会希望它是 100%？
> 因为解码是**采样**而非取 argmax——temperature>0 时分布中的每个词都有被抽中的概率，这是刻意设计（保留多样性与可修正性）。
> 希望 P=100% 的场景：代码语法关键行、数学单步结果、结构化输出的固定字段——这些地方任何偏离都是错误，应设 temperature≈0 或直接 greedy decode。NLP7 的旋钮选择原则在这里落地。

> [!question]- 2. 如果没有因果掩码，第 4 站会发生什么？这对训练意味着什么？
> 没有掩码时，预测「巴黎」的位置可以直接看到答案本身（它在输入右侧的未来位置）——模型学会的唯一技能是「把右邻复制过来」，训练彻底失效。
> 这就是 GPT 式预训练必须配因果掩码的机制根源（DL8/BERT 对照的核心）。掩码让「预测未来」成为需要真本事的任务而非作弊题。

> [!question]- 3. 一位工程师说「我们把 TTFT 从 900ms 优化到了 350ms」。列出两种可能的技术手段。
> 可能手段（任答两个）：
> ① **缩短 prefill**：系统提示词精简/压缩（prompt 压缩技术），prefill 是首字延迟的主成分；
> ② **投机解码 Speculative Decoding**：小模型先草拟几个 token，大模型并行验证，命中则一步产出多 token；
> ③ 更快的采样器/更少的去噪步数类比；④ 请求路由到离用户更近的数据中心降低网络 RTT。
> （TTFT 优化是大模型 Infra 领域当前最热的赛道之一。）

> [!question]- 4. 全课收束题：用不超过五句话，向一位完全没学过 AI 的朋友解释「ChatGPT 回答一个问题的时候发生了什么」。
> 参考答案（覆盖主干即合格）：
> 「你的话先被切成小块并翻译成一串数字；然后一个有几千亿个可调旋钮的网络层层加工这串数字——每一层都在问『上下文里什么和我有关』并吸收信息。加工完后，机器给出『下一个字是什么』的可能性排名，抽签抽出第一个字，把它接到句子末尾再跑一遍——如此循环直到说完。所有看似智能的回答，都是这套循环高速运转千万次的结果。」
