## 生活场景切入

你训练了一个「罕见病检测模型」，测试准确率 99%。兴冲冲汇报，领导问了一句：「这病人群里得病比例多少？」

「千分之一。」

「那我把所有来看病的人都判成健康，准确率也有 99.9%——比你的模型还高。」

一盆冷水浇醒了一个真理：**脱离数据分布谈准确率毫无意义**。评估模型就像司法取证——证据链上任何一处偷懒（看错了指标、用了泄漏的数据、只测了一次），结论都不可信。

## 核心概念拆解

### 概念 1：准确率的陷阱 —— 基线思维

上面的罕见病例子拆开看：1000 个病人里只有 1 个真患者。全判健康的「傻瓜模型」错 1 个对 999 个，准确率 99.9%。

**教训**：评估任何分类器之前，先算一个**傻瓜基线（baseline）**——多数类准确率、随机猜测水平。你的模型必须显著超过基线才有存在价值。

类别越不平衡，这个陷阱越深：欺诈检测（万分之一）、广告点击预测（千分之几）、故障预警……工业界的真实问题几乎全是严重不平衡的，「准确率」在这些场景基本退役。

### 概念 2：精确率、召回率、F1 —— 混淆矩阵的完全体

M10 已经见过四格混淆矩阵和三个指标，这里补全它们的关系与权衡（垃圾邮件场景，TP=正确拦截）：

```python
tp, fp, fn, tn = 40, 10, 20, 30

accuracy  = (tp+tn) / (tp+fp+fn+tn)
precision = tp / (tp+fp)        # 精确率：我说是的里面真是的有多少
recall    = tp / (tp+fn)        # 召回率：真的是的我抓出来多少
f1        = 2*precision*recall / (precision+recall)

print(f"准确率={accuracy:.2f} 精确率={precision:.2f} 召回率={recall:.2f} F1={f1:.3f}")
# 准确率=0.70 精确率=0.80 召回率=0.67 F1=0.729
```

**精确率和召回率天生是一对冤家**：收紧标准（提高阈值），报出来的更准但漏掉的更多；放宽标准，抓得全但误报泛滥。实测同一批样本在不同阈值下：

```text
阈值 0.7: precision=0.750  recall=0.600     ← 严格：准而不全
阈值 0.5: precision=0.667  recall=0.800     ← 折中
阈值 0.3: precision=0.500  recall=0.800     ← 宽松：全而不准
```

F1 是两者的调和平均，逼着两个都不能太差——需要单一数字汇报时用它。但更好的做法是**按业务代价选边**：癌症筛查保召回，邮件过滤保精确，没有免费的双高。

### 概念 3：K 折交叉验证 —— 别让运气决定结论

单次 train/test 划分有个隐患：如果测试集恰好偏简单，成绩虚高；偏难则被冤枉。**K 折交叉验证（K-Fold CV）** 的解法是把数据轮着考：

```text
5 折交叉验证：
第1轮: [考][训][训][训][训]
第2轮: [训][考][训][训][训]
...
第5轮: [训][训][训][训][考]     → 得到 5 个成绩，取平均±标准差
```

每一份数据都恰好当一次考官、四次教材——评估不再依赖某一次划分的手气。报告格式也更有信息量：

```text
单次划分：准确率 = 0.83          （就这一个数，信不信由你）
5 折 CV ：0.828 ± 0.017          （平均水平和波动一目了然）
```

波动大说明结果不稳定——可能是数据太少或模型对划分敏感。代价是训练成本 ×K 倍；实践中 5 折或 10 折是惯例。

### 概念 4：ROC 与 AUC —— 阈值之上的全景图

上一节看到阈值移动会改变精确率/召回率。那**不锁定阈值**，怎么评价一个模型的内在质量？

把阈值从最严扫到最松，每个位置记录两个量：

```text
TPR（真正例率）= 抓到的真患者 / 全部真患者      ← 越高越好
FPR（假正例率）= 误伤的健康人 / 全部健康人       ← 越低越好
```

画成曲线就是 **ROC 曲线**，曲线下面积就是 **AUC（Area Under Curve）**：

| AUC   | 含义                                                 |
| ----- | ---------------------------------------------------- |
| 1.0   | 完美：随便什么阈值都能完美排序                       |
| 0.9   | 随机抽一个正样本和一个负样本，90% 概率正样本得分更高 |
| 0.5   | 等于抛硬币（ROC 是对角线）                           |
| < 0.5 | 比瞎猜还差——把预测反过来用反而更好                   |

AUC 最妙的地方是**与阈值无关、对类别不平衡相对稳健**——它衡量的是模型的「排序能力」而非某个切点的对错。10 个样本手算验证（实际运行结果）：

```text
按置信度排序的样本 (置信度, 真实标签)，其中 P=4 个正、6 个负：
AUC = 0.680    ← 排序能力略好于随机，还有很大提升空间
```

工程惯例：**先看 AUC 确认模型有真本事 → 再按业务代价选工作阈值 → 最后用该阈值下的精确/召回做日常监控。**

### 概念 5：评估流程的总装清单

把本板块所有防坑措施串成一条流水线：

```text
① 数据划分：训练/验证/测试 分离，测试集锁进保险柜
② 基线先行：傻瓜模型的成绩先摆出来（多数类/随机）
③ 交叉验证：调参和比较都用 K 折平均 ± 标准差
④ 指标匹配业务：不平衡看 PR（精确率-召回率），排序任务看 AUC
⑤ 最终考核：全部决策做完后，测试集只许碰这一次
```

违反任何一条的「95% 准确率」，都值得多问一句：「在什么分布上？跟什么基线比？测了几次？」

## 自测一下

> [!question]- 1. 反诈骗系统报警 100 次，90 次是真的；全年真实诈骗 200 起中系统抓到 90 起。求精确率和召回率，若业务要求「宁可多报不可漏报」，该调高还是调低阈值？
> 精确率 = 90/100 = **90%**（报警的里真骗子的浓度）；召回率 = 90/200 = **45%**（一半骗子漏网）。
> 「宁可多报不可漏报」意味着漏报代价 >> 骚扰代价 → 应**调低阈值**换更高的召回率，接受精确率下滑。
> 这道题的业务翻译：反诈短信多发给几个疑似用户无伤大雅，漏掉一起真实诈骗损失惨重。

> [!question]- 2. 为什么交叉验证期间也不能碰测试集？「先用 CV 选模型再用测试集报告最终成绩」的正确姿势是什么？
> CV 的作用是**选方案**（超参数、模型种类），每次选择都在向参与评估的数据泄露一点偏好信息——CV 成绩因此带轻微乐观偏差。
> 测试集的价值恰恰在于它是唯一没参与任何选择的干净数据。正确顺序：CV 内完成所有比较与调参 → 定稿方案在测试集上跑一次 → 报告那个数字。
> 如果反复「测一下不满意再回去调」，测试集就退化成了第二个验证集，它的成绩重新变得可疑。

> [!question]- 3. 模型 A 的 AUC=0.85 但在工作阈值的精确率只有 30%；模型 B 的 AUC=0.78 但同阈值精确率 70%。哪个更适合上线？取决于什么？
> 取决于业务的**误报容忍度**。
> 若场景能承受较多误报、靠后续人工复核兜底（如初筛体检），A 更好——排序能力强，调低阈值即可捞回更多真阳性。
> 若报警直接触发昂贵行动（如自动冻结账户），B 更好——同样阈值下骚扰率低得多。
> 本题的核心：**AUC 衡量潜力（排序），精确率/召回率衡量某个具体工作点的表现**——上线选人看的是工作点，不是潜力。

> [!question]- 4. 同事说：「我在测试集上试了 20 组超参数，选了最好的那组，测试准确率 96%，稳了！」指出两处问题并给修复方案。
> 问题①：**测试集被当成调参集滥用**。20 次选择已把测试信息大量泄露给方案本身，96% 是乐观估计（ML4 的选择偏差在此重演）。
> 问题②：**没有不确定性度量**。单个数字无法区分「稳定的好」和「撞大运的好」。
> 修复：改用验证集（或 CV）完成这 20 组比较 → 选定参数后在测试集跑最后一次作为正式成绩 → 用 K 折的标准差补充稳定性说明。若条件允许，再收集全新数据复测一次最稳妥。
