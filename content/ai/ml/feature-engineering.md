## 生活场景切入

同一道菜，米其林大厨和食堂阿姨用一样的锅——差距全在**备料**。

机器学习同理。新手总以为提升效果靠换更高级的模型；老手的直觉是先回头检查数据：缺值填对了吗？量纲统一了吗？该拆的类别变量拆了吗？行业里流传已久的说法是：

> **Garbage in, garbage out.（垃圾进，垃圾出。）**
> 更精确的版本：数据决定上限，模型只能决定你多接近上限。

本课的四件基本功没有一件涉及高深数学，却是 Kaggle 竞赛和工业界涨点最稳定的手艺。

## 核心概念拆解

### 概念 1：缺失值处理 —— 空着的数据怎么办

真实数据永远有洞：用户不填年龄、传感器掉线、表格录入遗漏。三种处理策略：

| 策略                     | 做法               | 适用场景             | 风险         |
| ------------------------ | ------------------ | -------------------- | ------------ |
| 删行                     | 整条样本丢弃       | 缺失比例很小(<5%)    | 白白扔掉数据 |
| 填充（均值/中位数/众数） | 用统计量补上       | 最常用               | 低估真实波动 |
| 当作特征                 | 加一列「是否缺失」 | 「不填」本身有信息时 | 多一维要解释 |

第三种最容易被忽略却常常最关键：贷款审批里「收入空着」的人可能系统性地不同于「填了低收入」的人——**缺失本身就是信号**。

```python
import random
random.seed(2024)
n = 200
prices_missing = [round(random.uniform(50, 200), 1) for _ in range(n)]
for i in random.sample(range(n), 10):
    prices_missing[i] = None                      # 模拟 5% 缺失

valid = [p for p in prices_missing if p is not None]
filled = sum(valid) / len(valid)                  # 均值填充
print(f"缺失 {n-len(valid)} 条，均值填充 = {filled:.2f}")
# 缺失 10 条，均值填充 = 124.83
```

### 概念 2：标准化 —— 让所有特征平权说话

M8 已经预告过这个坑，现在正式解决。「年龄 (25~70)」和「年收入 (30000~800000)」放进同一个距离计算，收入直接把年龄淹没：

```python
import math

pts = [(30, 60000), (40, 80000), (25, 45000)]     # (年龄, 年收入)

def dist(a, b):
    return math.sqrt((a[0]-b[0])**2 + (a[1]-b[1])**2)

print(f"原始距离: {dist(pts[0], pts[1]):.0f}")     # 原始距离: 20000 ← 完全是收入的数字游戏

# Z-score 标准化：(x − 均值) / 标准差 → 变成均值 0、标准差 1
means = [sum(p[i] for p in pts)/3 for i in range(2)]
stds  = [math.sqrt(sum((p[i]-means[i])**2 for p in pts)/3) for i in range(2)]
norm  = [tuple((p[i]-means[i])/stds[i] for i in range(2)) for p in pts]
print(f"标准化后: {dist(norm[0], norm[1]):.3f}")   # 标准化后: 2.125 ← 年龄终于有了话语权
```

**口诀：基于距离的模型（KNN/K-Means/SVM）必做；基于树的模型（决策树/森林）不用做**——树只比较大小顺序，不在乎尺度。这条纪律在 M8 和 ML7 各出现过一次，现在你知道它属于特征工程的管辖范围了。

### 概念 3：One-Hot 编码 —— 给类别变量发身份证

模型只会算数，「北京/上海/深圳」这种文字没法直接喂。直觉方案「北京=1, 上海=2, 深圳=3」是**错的**——它暗示上海是北京的二倍、深圳比上海大，凭空制造了不存在的顺序关系。

正确姿势是 **One-Hot（独热编码）**：每个城市一列，命中打 1 其余为 0：

```python
import pandas as pd          # pandas 3.0.0 实测

df = pd.DataFrame({"城市": ["北京","上海","北京","深圳"],
                   "面积": [80, 100, 60, 90],
                   "价格": [500, 550, 380, 470]})
print(pd.get_dummies(df, columns=["城市"]).to_string())
#    面积   价格  城市_上海  城市_北京  城市_深圳
# 0   80  500     False    True    False
# 1  100  550      True   False    False
# ...
```

三列互斥的 0/1 彻底抹掉了虚假的序关系。代价是维度膨胀（100 个国家就多 99 列），类别特别多时要改用目标编码或嵌入向量——后者正是 NLP 板块 word embedding 的思想源头。

### 概念 4：分箱与交互特征 —— 把领域知识塞给模型

**分箱（Binning）**：把连续数值切成段变成类别。年龄 18~70 连续值对线性模型的贡献是单调直线；切成「青年/中年/老年」后，模型可以学出「中年最高、老年回落」的非单调规律。

```python
import pandas as pd

ages = pd.Series([18, 22, 25, 32, 45, 51, 67, 70])
bins = pd.cut(ages, bins=[0,30,50,100], labels=["青年","中年","老年"])
print(bins.value_counts().to_string())
# 青年 3 | 中年 2 | 老年 3
```

**交互特征（Interaction）**：把两个特征相乘组合。「单价 = 价格/面积」比单独的价格和面积更有预测力；「工龄 × 学历」可能比两者各自更能解释薪资。这类手工组合无法被线性模型自动发现——**领域知识在这里直接兑换成模型性能**。

深度学习的卖点恰恰是「自动学交互」，但那需要海量数据；小数据场景下，人工特征工程依然是性价比之王。

### 概念 5：判断框架 —— 什么时候做什么

把四件事收进一张速查表：

| 手法       | 一句话判断                         | 谁需要                                 |
| ---------- | ---------------------------------- | -------------------------------------- |
| 缺失值处理 | 有洞吗？洞本身有信息吗？           | 所有模型                               |
| 标准化     | 特征量纲悬殊 + 距离/梯度类模型？   | KNN/K-Means/SVM/神经网络 ✅<br>树类 ❌ |
| One-Hot    | 类别特征被编成了假序数？           | 线性/SVM/神经网络 ✅<br>树类可不做     |
| 分箱/交互  | 关系非单调？领域知识能表达成组合？ | 线性类模型收益最大                     |

最后一条心法：**每加一个特征都要问「这反映了我对问题的什么理解？」**——答不上来的特征堆砌只会增加过拟合风险（ML4 的账还记得吧）。特征工程的本质不是搬运数据，而是把人类知识翻译成模型听得懂的语言。

## 自测一下

> [!question]- 1. 「学历：高中=1, 本科=2, 硕士=3」这种编码和 One-Hot 的区别？学历场景哪个更合适？
> 数字编码隐含了**等距有序假设**：本科−高中 = 硕士−本科 = 1，即每升一级效果相同。
> 学历恰好大体满足单调性，数字编码反而合理且省维度（保留序信息）；而城市、颜色这类无序类别必须 One-Hot。
> 结论：**有序类别可用序数编码，无序类别必须 One-Hot**——判断依据是「类别之间有没有真实的程度关系」。

> [!question]- 2. 为什么随机森林不需要标准化，KNN 却必须？从两者的数学机制找根因。
> 决策树每次分裂只问「x_j > 阈值？」——比较发生在单个特征内部，尺度变换后阈值跟着缩放，结果完全不变。
> KNN 计算跨特征的欧氏距离，不同量纲直接相加——大数值特征独裁整个距离。
> 根因一句话：**树看「序」，距离模型看「量」**。凡是看量的（KNN/K-Means/SVM/线性模型+梯度下降），都得管好量纲。

> [!question]- 3. 训练集标准化用了全体数据的均值标准差，有什么问题？
> 这是经典的**数据泄露（data leakage）**：测试集的信息（通过全局统计量）提前渗入了训练过程，评估成绩虚高，上线后现出原形。
> 正确流程：只用训练集算均值/标准差 → 用它们去变换训练集和测试集。生产环境还要把这些统计量存下来供线上预测使用。**任何用到「全体数据」的预处理都值得警惕**（缺失率统计、目标编码同理），这是 ML9 交叉验证之外另一大评估陷阱。

> [!question]- 4. 房价数据里有「面积」「总价」两列，直接一起喂给线性回归合适吗？怎么改进？
> 不合适：总价 ≈ 单价 × 面积，两列高度共线（相关系数接近 1），线性回归的权重会变得不可解释、方差巨大。
> 改进方向按信息价值排序：构造**单价 = 总价/面积**作为交互特征（往往比原两列都有用）；或删其一保留信息更丰富的；或改用带正则化的模型（L2 会自动压制冗余权重，ML4 已铺垫）。
> 这题展示特征工程的另一面：**加特征重要，减特征同样重要**。
