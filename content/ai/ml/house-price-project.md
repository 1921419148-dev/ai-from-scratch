## 生活场景切入

前面九课学了一堆零件：损失函数（ML2）、梯度下降（M7）、特征工程（ML8）、评估方法（ML9）……但零件堆在车间里造不出车。

这一课把它们**按真实工程的顺序总装**。场景是最经典的入门问题——房价预测。别嫌它俗：Kaggle 竞赛史上最著名的入门题就是它，而且「给定几个属性估一个数值」的结构，与估值、销量、能耗等无数业务问题是同构的。

## 核心概念拆解

### 第 0 步：任务定义

```text
输入：面积（㎡）、卧室数、房龄
输出：价格（万元）
类型：回归（连续数值）
成功标准：测试集 RMSE 显著优于基线
```

先写清这四行再动手——任务定义含糊是项目翻车的第一原因。

### 第 1 步：生成并检查数据

真实项目这里应该是读 CSV + `df.describe()`；教学版用可控的合成数据（隐藏规律 `价格 = 0.7×面积 + 3×房间 − 0.5×房龄 + 20` 加噪声），好处是我们知道标准答案，能检验模型找得对不对：

```python
import random, math
import numpy as np

random.seed(2024)
n = 200
areas  = [random.uniform(40, 160) for _ in range(n)]
rooms  = [max(1, int(a//30 + random.gauss(0,1))) for a in areas]
ages   = [random.uniform(0, 30) for _ in range(n)]
prices = [0.7*a + 3*r - 0.5*g + 20 + random.gauss(0,8)
          for a, r, g in zip(areas, rooms, ages)]
```

**特征体检**——算每个特征与价格的相关系数（P9 学过的 r；实际运行结果）：

```text
corr(area)  = 0.950    ← 强正相关：面积越大越贵，符合常识 ✓
corr(rooms) = 0.774    ← 正相关，且与面积部分重叠（大房子房间多）
corr(age)   = -0.131   ← 弱负相关：老房略便宜
```

三个信号都指向合理方向，没有明显脏数据。注意 rooms 与面积相关性高——它们有信息重叠，线性模型会自动分摊权重，这正是多元回归比单变量聪明的地方。

### 第 2 步：划分数据 —— 先切后看

```python
idx = list(range(n)); random.shuffle(idx)
tr, te = idx[:160], idx[160:]        # 80/20 划分
```

纪律重申：划分必须在任何分析之前完成（严格来说相关系数也该只对训练集算——本课为了篇幅从简，正式项目请守规矩，ML9 的教训）。教学场景我们保留全量统计以便对照真值。

### 第 3 步：基线 —— 先给傻瓜模型记个分

```text
基线策略：不看任何特征，永远猜训练集的平均价格 ≈ 88 万
它的测试 RMSE ≈ 价格的标准差 ≈ 33 万
```

这就是要打败的及格线。任何声称「有效」的模型必须显著低于 33 万。

### 第 4 步：训练多元线性回归

模型升级为：

```text
价格 = b + w₁×面积 + w₂×房间 + w₃×房龄
```

四个参数用正规方程一步解出（闭式解，ML2 方法一的多元版）：

```python
X  = np.column_stack([np.ones(n), areas, rooms, ages])   # 第一列全 1 对应截距
yv = np.array(prices)
theta = np.linalg.lstsq(X, yv, rcond=None)[0]

print("theta:", theta.round(3))
# theta: [16.08   0.728  3.091  -0.41 ]
#        ↑截距   ↑面积   ↑房间   ↑房龄
```

对照真值解读：

| 参数 | 学到  | 真值 | 解读                |
| ---- | ----- | ---- | ------------------- |
| w₁   | 0.728 | 0.7  | 每平米约值 0.73 万  |
| w₂   | 3.091 | 3.0  | 每间卧室贡献约 3 万 |
| w₃   | −0.41 | −0.5 | 房龄每老一年贬 4 千 |

**模型几乎完美地恢复了隐藏规律**——注意它是在噪声 σ=8 的干扰下做到的。更妙的是权重的符号和量级都可以向人类解释：「每平米七千三」听起来就像中介会说的话。

### 第 5 步：双指标验收

```text
全量拟合：R² = 0.930    RMSE = 7.82 万
测试集：  test RMSE = 6.57 万
```

- **R² = 0.93**：三个特征解释了 93% 的价格波动（ML2 的 R² 在此上岗）
- **RMSE ≈ 6.6~7.8 万 vs 基线 33 万**：误差砍掉近五倍，远超及格线
- RMSE 与噪声水平 σ=8 同量级：模型已经把「能学的规律」学干净了，剩下的误差本质上是随机噪声——**继续换更复杂的模型也不会有明显收益**（这个判断比分数本身更有价值）

### 第 6 步：交付预测

```python
new_house = np.array([1, 100, 3, 10])      # 100㎡ / 3 卧 / 10 年
print(f"预测: {float(new_house @ theta):.1f} 万")
# 预测: 94.0 万
```

手工核对一遍：`20 + 0.728×100 + 3.09×3 − 0.41×10 ≈ 94` ✓。至此一个最小但完整的机器学习产品闭环走通。

## 自测一下

> [!question]- 1. 本项目的基线 RMSE 为什么约等于「价格的标准差」？
> 「永远猜均值」的每个误差 = 该样本价格 − 平均价。对这些误差求均方根，恰好就是标准差的定义（M10：σ 是偏离均值的均方根）。
> 这不是巧合而是通例：**均值基线的 RMSE 恒等于目标变量的标准差**。所以拿到新回归任务，瞄一眼 y 的标准差就知道及格线画在哪。

> [!question]- 2. 测试 RMSE（6.57 万）已经接近噪声水平 σ=8 万，同事仍建议上 XGBoost 冲一冲，你怎么评估这个建议？
> 先算理论空间：模型无法预测噪声成分，所以最优 RMSE ≥ σ=8 万附近——当前 6.57 万已在这个量级，XGBoost 的提升上限非常有限（可能只有小数点级别的改善）。
> 更值得做的反而是：① 收集更多信息量大的特征（地段、学区——当前三个特征只解释了 93%）；② 检查残差是否有系统性模式（比如大面积房源偏差更大）。**判断瓶颈在「模型不够强」还是在「信息不够多」，是资深工程师与新手的分水岭**。

> [!question]- 3. 如果把「房龄」的单位从年改成十年（数值缩小 10 倍），模型的什么会变？什么不变？需要重新标准化吗？
> 变的：w₃ 会放大 10 倍（−0.41 → 约 −4.1），因为每单位现在代表十年。
> 不变的： predictions（数学上完全等价的重新参数化）、R²、RMSE、其他特征的权重。
> 正规方程/树类模型不需要标准化也能正常工作（闭式解对尺度不敏感）。但如果改用梯度下降求解，就必须标准化——否则房龄列梯度极小、收敛极慢（ML2 自测题 2 的教训）。

> [!question]- 4. 老板要求「给一套模型没见过的新房子估价」。这套房子如果面积高达 500㎡（训练数据最大 160㎡），你敢直接报模型输出吗？
> 不敢直接报。这是**外推**（ML2 自测题 4 的坑）：训练数据覆盖 40~160㎡，模型在范围外的行为没有任何数据背书，线性外推可能严重失真（别墅市场的定价逻辑不同）。
> 专业做法：① 明确告知模型的有效范围；② 对超出范围的请求转人工评估或标注低置信度；③ 若此类需求常见，补充大户型数据重新训练。**交付的不只是模型，还有模型的能力边界说明**——这是工程责任心的体现。
