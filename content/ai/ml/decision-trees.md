## 生活场景切入

你妈给你安排相亲，回来后问你「成不成」，你脑内跑了一遍流程：

```text
三观念正吗？
├─ 不正 → 拒绝 ❌
└─ 正 → 有共同话题吗？
    ├─ 没有 → 拒绝 ❌
    └─ 有 → 聊得舒服吗？
        ├─ 不舒服 → 再观察 🤔
        └─ 舒服 → 成了！✅
```

每个内部节点是一个**是非题**，每个叶子是一个**结论**。这就是决策树——可能是唯一一个人类不用学数学也能看懂的机器学习模型。医生诊断、贷款审批、故障排查，专家脑子里都装着这样的树。

## 核心概念拆解

### 概念 1：决策树怎么长出来

训练数据带标签，算法要自动挑出「最值得先问的问题」。衡量标准来自 M4 的信息熵：

```text
熵 H = 数据的混乱程度（标签越混杂熵越大）
信息增益 = 问这个问题前后熵下降了多少   —— 增益最大者优先提问
```

经典小数据集实测（14 天的天气与是否打网球；Python 实际运行结果）：

```python
import math

data = [("晴","否"),("晴","否"),("阴","是"),("雨","是"),("雨","是"),
        ("雨","否"),("阴","是"),("晴","否"),("晴","是"),("雨","是"),
        ("晴","是"),("阴","是"),("阴","是"),("雨","否")]

def entropy(rows):
    n = len(rows)
    p_yes = sum(1 for _, y in rows if y == "是") / n
    h = 0.0
    for p in (p_yes, 1 - p_yes):
        if p > 0:
            h -= p * math.log2(p)
    return h

H_all = entropy(data)
print(f"H(全部) = {H_all:.3f}")            # H(全部) = 0.940

# 按「天气」划分后的条件熵
n = len(data)
for v in ["晴", "阴", "雨"]:
    sub = [d for d in data if d[0] == v]
    print(v, len(sub), f"H={entropy(sub):.3f}")
# 晴 5 H=0.971 | 阴 4 H=0.000 | 雨 5 H=0.971

H_cond = sum(len([d for d in data if d[0]==v])/n * entropy([d for d in data if d[0]==v])
             for v in ["晴","阴","雨"])
print(f"H(Y|天气) = {H_cond:.3f}")          # H(Y|天气) = 0.694
print(f"信息增益 = {H_all - H_cond:.3f}")   # 信息增益 = 0.247
```

注意「阴天」那组的熵是 **0**：4 个阴天全部打了网球——问完这个分支直接得出确定答案。而「打网球与否和天气关系不大」的其他特征增益会小得多，自然排到后面再问。**决策树就是贪心地按信息增益排队提问**，直到每片叶子的标签足够纯。

### 概念 2：决策树的优缺点

| 优点                                 | 缺点                           |
| ------------------------------------ | ------------------------------ |
| 人类可直接阅读、解释（「白盒模型」） | 单棵深树极易过拟合             |
| 不需要特征缩放/归一化                | 对数据微小扰动极其敏感         |
| 天然处理类别特征                     | 直线边界思维，复杂关系表达吃力 |

过拟合有多严重？不加限制时树会一直长到每个叶子只剩一个样本——等于逐条背诵训练数据，ML4 的老毛病原样复发。所以工程上都要给树「修剪」（限制深度、叶子上最少样本数）。

但修剪过的单棵树又不够准……这个两难由随机森林优雅化解。

### 概念 3：随机森林 —— 一群歪脖子树投票

```text
随机森林 = 训练几百棵「故意搞坏」的小树 → 每棵投票 → 多数获胜
```

妙处在于「故意搞坏」的两层随机性：

1. **数据随机（Bootstrap）**：每棵树只看一份有放回抽样的数据副本——有的树恰好没见过某些难点
2. **特征随机**：每次分裂只在随机一小撮特征里挑——逼着不同的树发展出不同视角

单棵树可能各有偏见，但**几百棵视角各异的树多数投票后，个体偏差互相抵消**。这背后有严格的统计学依据（方差缩减），不过用生活经验理解就够了：问一个人不如问一群独立思考的人。

数值感受一下（含 10% 标签噪声的二分类数据，真实规则 `x₁ > 0.5`，实际运行结果）：

```text
单棵决策桩（深度1）在噪声数据上: 准确率 ≈ 0.915
9 棵随机森林 × 30 次重复实验:     平均准确率 ≈ 0.915
```

有趣的发现：噪声把准确率的理论上限压到约 0.90（10% 标签本身就是错的），此时森林的价值不在刷高上限，而在**稳定**——单棵树换个随机种子成绩忽上忽下，森林的成绩几乎纹丝不动。**集成牺牲了个性，买来了稳健**。当数据更复杂、单模型方差更大时，这个差距会拉到肉眼可见。

### 概念 4：集成学习 —— 三种流派一句话

```text
Bagging（随机森林所属）：并行训练多个模型，投票取平均 → 主要降方差（治过拟合）
Boosting（如 XGBoost）：串行训练，每个新模型专攻前面犯的错 → 主要降偏差（治欠拟合）
Stacking：训练一个「元模型」学着组合各家输出
```

记住一句话就够：**Bagging 让一群人独立表决，Boosting 让学生接力纠错。** Kaggle 竞赛表格数据的常胜将军 XGBoost/LightGBM 都是 Boosting 家族——「传统方法在结构化数据上仍碾压深度学习」是行业共识。

## 自测一下

> [!question]- 1. 为什么决策树「不需要特征归一化」，而线性回归/KNN 需要？
> 决策树只关心「x 大于还是小于某个阈值」——比较的是顺序，不是距离或尺度。「年龄 40 > 阈值 35」和「收入 80000 > 阈值 60000」在算法眼里没有本质区别。
> 线性回归的权重会被大尺度特征支配、KNN 直接算距离被大数值淹没（M8 的教训），它们必须先归一化。**是否依赖「距离/尺度」决定了要不要归一化**这一条判断标准，可以推广到几乎所有算法。

> [!question]- 2. 随机森林的两层随机性分别防什么病？
> **数据随机（Bootstrap）防相关性**：如果所有树都看同一份完整数据，它们会长得几乎一样、犯同样的错——投票变成走形式。数据副本让树彼此独立，错误才能互相抵消。
> **特征随机防强者垄断**：若某个超强特征永远在场，每棵树的根节点都会选它，树又趋同了。限制候选特征逼着弱特征也有出头之日，增加多样性。
> 两招合起来一句话：**集成的威力 ∝ 单模型的多樣性，而不是单模型的精度**。

> [!question]- 3. 医院要用 AI 辅助诊断并说服病人相信结论，决策树和神经网络哪个更合适？说出权衡。
> 首选决策树（或其可解释变体）。理由：白盒模型可以把推理链讲给病人听——「肿瘤直径 > 3cm 且年龄 < 50，所以建议进一步检查」——这是知情同意的法律与伦理要求。
> 神经网络精度可能更高，但黑盒推理难以服人。医疗、信贷、司法等高风险领域的监管普遍要求**可解释性优先于极致精度**。当然折中方案存在（用复杂模型预测 + 用简单模型事后解释），ML8 特征工程之后可以再回味这道题。

> [!question]- 4. 本课示例里森林的平均准确率并不比单棵树高（都是 0.915），这算集成失败了吗？
> 不算。那个实验里准确率的上限被 10% 标签噪声锁死（≈0.90），任何模型的期望表现都在这条线上下。
> 森林真正的收益体现在**方差**：单棵树的成绩随随机种子波动明显，30 次实验的森林平均却极其稳定。生产环境要的是「明天重新训练一次结果也不会突然变差」——稳健性本身就是价值。若换更复杂数据（单树欠拟合或高方差场景），森林会同时赢在均值和方差两端。
