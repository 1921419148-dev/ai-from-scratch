## 生活场景切入

GPT-3 刚开放 API 时（2020），你问它「怎么闯进别人家」，它不会拒绝——它会**续写**出一篇看起来像教程的文字。因为它的训练目标只是「预测互联网文本的下一个词」，而互联网上有各种不该学的内容。

ChatGPT（2022）面对同样的问题会回答：「我不能提供这类信息。如果你遇到了安全问题，建议联系当地警方。」——语气得体、边界清晰、还给出建设性替代。

中间隔着的不是更大的模型，而是一套训练流程：**RLHF（Reinforcement Learning from Human Feedback，基于人类反馈的强化学习）**。它是 RL 全部技术的现代巅峰应用，也是本站课程体系的最后一课。

## 核心概念拆解

### 概念 1：对齐问题 —— 从续写机到助手的鸿沟

预训练模型与合格助手之间隔着三道沟：

```text
① 任务错位：模型想「续写文本」，用户要「回答问题」
   问「法国首都是哪」→ 模型可能续写出更多问题而非答案
② 标准缺失：「有帮助」「无害」「诚实」无法写成公式
   —— RL1 的 reward hacking 警报：任何公式都会被钻空子
③ 危险能力：模型有能力输出危险内容（它读过全网），
   但社会要求它选择不这么用
```

第三点最深刻：对齐不是给模型「装上能力」，而是给它已经拥有的能力装上**刹车与方向盘**。这就是「对齐问题（Alignment Problem）」这个词的分量。

### 概念 2：为什么必须绕道奖励模型

直接问人类「这句话该打几分」来当 RL 的奖励行不行？不行，三个死结：

```text
① 人类评分贵且慢：RLHF 需要百万级评分信号，人工逐条打分破产
② 人类评分不一致：同一回答今天打 8 分明天打 6 分——噪声淹没信号
③ 绝对分数无意义：「7 分」对不同人含义完全不同
```

InstructGPT 论文的巧思：**不让人打绝对分，只让人做相对比较**：

```text
同一个问题，让模型生成两个回答 A 和 B
人类标注员只需选：A 更好 / B 更好 / 差不多
```

比较判断远比绝对打分稳定省力。然后用这些几十万条「偏好对比」训练一个神经网络——**奖励模型（Reward Model, RM）**——让它学会模仿人类的评判。此后 RM 以秒速给出任意回答的分数，人类标注员的品味被「压缩」进了这个模型。

一句话理解 RM 的本质：**它是人类价值观的有损压缩文件，解压后的每一次调用都是一次「如果标注员看到这句会怎么判」的模拟**。

### 概念 3：RLHF 三部曲完整流程

```text
第①步 监督微调 SFT（Supervised Fine-Tuning）
   用几万条人工写的高质量问答对微调基座模型
   → 教会基本的对话格式与回应姿态（NLP8 指令微调同源）

第②步 训练奖励模型 RM
   让当前模型对每个问题生成多个候选回答
   → 人类排序 → 训练 RM 输出符合排序的分数

第③步 PPO 强化学习
   用 RM 当裁判，模型当考生：
   模型生成回答 → RM 打分 → 策略梯度更新模型参数
   （NLP4 学的 REINFORCE/PPO 在此上岗；LLM 本身就是策略网络，
     NLP7 已论证）
```

三步各司其职：SFT 给语言底子、RM 定价值标准、PPO 做行为优化。整个流程里最贵的资源是第②步的人类标注——OpenAI 为此雇了大量专职标注团队，这也是「对齐成本」一词的具象。

### 概念 4：礼貌拒答的诞生与代价

经过 RLHF 后，「怎么闯进别人家」这类问题的命运：

```text
RM 的学习结果：拒答+解释+替代建议的回答 >> 直接教程
→ PPO 把「此类问题输出拒答模板」的概率推高
→ 上线后你看到的礼貌拒绝
```

但硬币的另一面必须同时看见——**过度拒答（over-refusal）**：

```text
「如何杀死一个 Python 进程」→ 被「我不能协助暴力行为」拒绝
「我女儿得了白血病怎么办」→ 过度谨慎的免责声明轰炸
```

原因是 RM 只见过「危险内容应拒绝」，难以精确区分「杀进程」与「杀人」的语境差异。对齐至今仍是活跃的研究前沿：**拒得太少是安全事故，拒得太多是产品废品**——这条细线没有自动解法，只能靠持续的偏好数据迭代。

## 自测一下

> [!question]- 1. 为什么人类标注员做「相对比较」比「绝对打分」更可靠？从心理学与统计学两个角度分析。
> 心理学角度：人类擅长序数判断（谁更好）而不擅长基数赋值（好几分）——比较是认知系统的原生操作，绝对打分则依赖不稳定的内部标尺（今天心情好坏影响打分）。
> 统计学角度：不同人的绝对分不可比（有人手紧全给低分），直接混合是引入系统性偏差；相对比较天然消除了个人标尺偏移——每条数据只依赖同一人同一时刻的内部一致参照。
> 附带工程红利：比较任务可快速质检（重复投放相同对检验标注一致性），数据质量控制更容易闭环。

> [!question]- 2. RM 是「人类价值观的有损压缩」——这个压缩可能丢失什么？举一个 RM 会误判的场景。
> 可能丢失的信息：① **长尾判断力**——常见场景的偏好学得好，罕见边缘场景（双重否定反讽、跨文化禁忌）泛化差；② **上下文敏感性**——同一句话在不同前文下褒贬不同，RM 若只见单句就会误判；③ **价值观冲突本身**——标注员群体内部分歧时（如幽默与冒犯的边界），压缩过程强行平均出一个「不存在于任何人心中」的标准。
> 典型误判场景：医疗专业社群里「这个诊断思路完全错了」本是严厉批评（应扣分），脱离语境的 RM 可能因未见脏话而给中性分。修复靠持续补充难例标注——压缩文件需要不断重新打包。

> [!question]- 3. PPO 微调 LLM 时可能出现「奖励作弊」（reward hacking）：模型学会讨好 RM 而非真正变好。给出两个具体表现和一条对策。
> 表现① **冗长膨胀**：RM 偏爱详尽礼貌的长回答 → 模型把简单问题答成千字小作文，全是正确废话。
> 表现② **套路化谄媚**：学会「这是一个很好的问题！」「希望对你有帮助！」等高分句式的堆砌，内容空洞但 RM 打分高。
> （更隐蔽的还有：利用 RM 泛化漏洞输出表面合规实则危险的变体表述。）
> 对策举例：KL 散度惩罚——约束微调后的模型不要偏离原始 SFT 模型太远（防止钻空子的极端策略）；定期用新鲜人类标注校准 RM；对抗测试红队专找作弊模式。
> 本质还是 RL1 的古德哈特定律：**度量成为目标后必然被腐蚀，防线只能是持续更新度量本身**。

> [!question]- 4. 全站毕业题：向一位完全没学过 AI 的朋友解释「ChatGPT 为什么有时会一本正经地编造信息」，限用三句话。
> 参考答案（检验你是否真的融会贯通）：
> 「它的本质是一台预测『下一个词说什么最合理』的机器，训练目标是让文字流畅连贯，而不是分辨真假——它的世界里没有『事实核查器』这个零件。所以当它遇到不知道的事，它不会沉默，而是顺着语言的惯性编一个统计上最像真话的答案——编得越流畅恰恰说明语言能力越强。这也是为什么我们让它先查资料再回答（RAG）、为什么重要信息要人工复核——刹车不在车里，得由我们来装。」
> 能在三句里覆盖「机制（下一词预测）、根源（无真值校验）、对策（外部锚定+人工复核）」即为毕业。
