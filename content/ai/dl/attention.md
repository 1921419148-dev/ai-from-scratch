## 生活场景切入

在图书馆查「文艺复兴对科学的影响」。你的动作：

1. 心里带着**查询意图**（Q）：我要找「艺术与科学的关联」
2. 扫过书架每本书的**书脊标签**（K）：判断哪本可能相关
3. 相关的书翻开细读其**内容**（V），按相关程度分配注意力

三样东西各司其职：Q 是「我在找什么」，K 是「我是什么」，V 是「我携带的信息」。注意力的全部魔法就是**用 Q 和 K 的匹配度，给 V 加权平均**。

## 核心概念拆解

### 概念 1：公式逐项解剖

缩放点积注意力的完整公式只有一行：

```text
Attention(Q, K, V) = softmax(QKᵀ/√dₖ) · V
```

| 部件      | 干什么               | 图书馆类比               |
| --------- | -------------------- | ------------------------ |
| `QKᵀ`     | 所有查询对所有键打分 | 我的问题 × 每本书的标签  |
| `÷√dₖ`    | 除以向量维度的平方根 | 防止维度大时打分过于尖锐 |
| `softmax` | 分数变权重（和为 1） | 注意力配额 100%          |
| `· V`     | 按权重加权求和值     | 按比例摘录各书内容       |

### 概念 2：手算一遍 —— 三个 token 的自注意力

设 3 个 token、维度 dₖ=4，Q=K=V 用同一组手工向量（实际运行结果）：

```python
import math

Q = [[1,0,1,0],
     [0,1,0,1],
     [1,1,1,1]]
d_k = 4

def softmax(xs):
    m = max(xs); e = [math.exp(v-m) for v in xs]; s = sum(e)
    return [v/s for v in e]

# ① 打分 + 缩放
scores = [[sum(q[i]*k[i] for i in range(4))/math.sqrt(d_k) for k in K] for q in Q]
# [[1.0, 0.0, 1.0], [0.0, 1.0, 1.0], [1.0, 1.0, 2.0]]

# ② softmax 变权重
weights = [softmax(r) for r in scores]
# row0: [0.422, 0.155, 0.422]   ← token0 对自己和对 token2 各分 42% 注意力

# ③ 加权求和值向量
out = [[sum(w[j]*V[j][i] for j in range(3)) for i in range(4)] for w in weights]
```

读结果的方式：每一行的权重和恰好为 1（softmax 的性质）；第三个 token 因为和谁都「像」（全 1 向量），在所有行里都拿到高权重。**注意力矩阵就是一张「谁该看谁、看多少」的关系表。**

### 概念 3：自注意力 —— 序列照镜子

上面 Q=K=V 同源的做法叫**自注意力（Self-Attention）**：序列中的每个位置同时发出查询、提供键值，让词与词直接交换信息。

它解决的具体问题举例：「小明把书递给小红，因为**她**想读」——「她」指谁？RNN 只能把信息挤进一条隐藏状态慢慢传；自注意力让「她」这个位置的查询直接命中「小红」的键，一步完成指代消解。

工程上 Q/K/V 不是原始向量而是三个可学习的线性投影（`W_Q·x` 等）——让网络自己学出「该按什么维度找相关」。多头注意力则是并行跑多套投影，各自关注不同模式（语法关系/指代关系/语义相似……）再拼接。

### 概念 4：因果掩码 —— GPT 不许偷看答案

语言建模要求「预测下一个词时只能依赖前文」。但注意力天生全图连通——第 5 个位置能看见第 6 个词，等于考试偷看标准答案。

**因果掩码（Causal Mask）** 的做法粗暴而有效：把分数矩阵的上三角（未来位置）填成 −∞，softmax 后这些位置的权重精确为 0。手算验证（实际运行结果）：

```python
masked = scores[1][:]          # token1 的打分行 [0.0, 1.0, 1.0]
masked[2] = float('-inf')      # 掐断对 token2（未来）的视线

w = softmax(masked)
print([round(v, 3) for v in w])
# [0.269, 0.731, 0.0]           ← 未来位置的权重严格归零 ✓
```

GPT 系列的全部秘密之一就这一行掩码：加上它，注意力变成严格的「只准往回看」，整个模型才能合法地做「预测下一个词」的训练。BERT 则不加掩码（双向看全文），所以它擅长理解而非生成——这对兄弟的分野从一行代码开始。

### 概念 5：注意力 vs RNN —— 直达电梯取代盘山公路

| 维度       | RNN                    | 自注意力               |
| ---------- | ---------------------- | ---------------------- |
| 信息路径   | 逐步接力，远距衰减     | **任意两点一步直达**   |
| 并行训练   | 必须串行（有状态依赖） | 全序列并行（GPU 吃满） |
| 长程依赖   | 梯度消失重灾区         | 路径长度恒为 1         |
| 计算复杂度 | O(n)                   | O(n²)（长序列的代价）  |

最后两行揭示了完整的权衡图景：注意力用平方级的计算开销换来了「任意距离无损连接 + 完美并行」。GPU 时代的算力红利恰好偏爱这种结构——DL9 里 Transformer 把它推上王座，本质上是一场「算法形态与硬件特性的双向奔赴」。

顺带解开 DL7 的悬念：Transformer 出现后 LSTM 在大规模 NLP 中迅速退场，但 RNN 的思想并未作废——隐藏状态的记忆观、门控设计、语言建模任务全部被继承。**学过的东西不会白学，只会换个地方继续发光。**

## 自测一下

> [!question]- 1. 公式里除以 √dₖ 的作用是什么？不除会发生什么？
> 点积的方差随维度 dₖ 线性增长——维度高时分数动辄几十上百，softmax 进入饱和区：最大的一个分数拿走几乎全部注意力权重，其余趋近于零。
> 后果是梯度消失（softmax 饱和区导数≈0）且注意力退化成「硬选择」，失去软性的信息混合能力。除以 √dₖ 把方差拉回 1 量级，保持分布「软而不瘫」。这是又一个「数值稳定决定架构细节」的经典案例。

> [!question]- 2. 「她」的指代消解例子里，如果换成 RNN 会怎么处理？说明两者机制差异。
> RNN：「她」之前的信息必须逐词压缩进隐藏状态流过来——「小明」「递书」等信息经过多步 tanh 重写后已高度稀释，「她」能否正确解析全凭运气（取决于距离和中间内容的干扰）。
> 自注意力：「她」的查询向量直接与全句所有位置的键计算匹配度，命中小红只需一次点积+一次 softmax——无论相隔 2 个词还是 200 个词，机制完全相同。
> 一句话总结：**RNN 是接力赛，注意力是广播找人**。

> [!question]- 3. 为什么 BERT 不加因果掩码而 GPT 必须加？从两者的训练目标推导。
> GPT 的目标是「预测下一个词」（生成式）：若允许看到未来，模型直接把答案抄进输入——训练彻底失效，掩码是逻辑必需。
> BERT 的目标是「完形填空」（遮住 15% 的词猜它们）：预测被遮词时本来就该利用全部上下文（前后都要看），掩码反而有害。
> 结论：**掩码不是注意力的属性，而是训练目标的镜像**——先定任务，再定结构。这也是「理解派 BERT vs 生成派 GPT」路线分歧的技术起点。

> [!question]- 4. O(n²) 复杂度意味着什么？举出两个因此产生的工程现实。
> 序列长度翻倍，注意力计算量翻四倍。现实后果：
> ① **上下文窗口昂贵**：GPT 类模型的「最大 token 数」直接受此约束——128K 上下文的成本远不止线性增长，这是各家竞逐长上下文时的核心技术壁垒；
> ② **长文档处理需要专门技术**：稀疏注意力、滑动窗口、FlashAttention（优化显存访问而非改数学）等一整条研究线都在跟 n² 作斗争。
> 反过来，n<几千的常规场景下这点代价完全值得——换来的是 RNN 梦寐以求的并行训练速度。
