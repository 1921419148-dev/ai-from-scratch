## 核心概念拆解

### 概念 1：调参优先级 —— 别在错误的旋钮上使劲

按投入产出比排序：

```text
① 学习率 lr          —— 影响最大，错了全盘皆输（M7 的三种命运）
② 模型容量           —— 过拟合/欠拟合的分界（ML4）
③ 数据质量与增强     —— 上限所在（ML8）
④ 优化器             —— Adam 先用上再说（本课概念 3）
⑤ batch size         —— 与 lr 联动（本课概念 4）
⑥ 正则化强度         —— 微调阶段再精修（ML4）
⑦ 其余花活           —— 确认前面都对之前别碰
```

反模式警告：新手最爱调网络层数和花哨模块——那是优先级第⑦项。**90% 的训练问题出在前两项。**

### 概念 2：学习率扫描 —— 实测数据说话

在带噪声的二次损失面上扫描学习率，每个档位跑 20 个种子取平均末段损失（实际运行结果）：

```text
lr=0.001 : final loss ≈ 4.467    ← 太小，200 步还在半路
lr=0.01  : final loss ≈ 0.016    ← ★ 本任务最优
lr=0.05  : final loss ≈ 0.052
lr=0.1   : final loss ≈ 0.104
lr=0.5   : final loss ≈ 1.070    ← 开始震荡
lr=1.0   : final loss ≈ 435.277  ← 发散爆炸
```

两个工程惯例由此而来：

1. **数量级扫描**：先粗扫 0.0001/0.001/0.01/0.1/1 找到量级，再在该量级内细调——比线性网格高效十倍
2. **LR Range Test**：从小到大逐步加 lr 记录损失，损失开始上升的拐点往回退一个量级即良好起点（fastai 库已内置）

### 概念 3：优化器 —— Adam 在峡谷里的统治级表现

峡谷形损失面 `L = w₁² + 100·w₂²` 上对比两大优化器（实际运行结果）：

```text
500 步后与最优点的距离：
  SGD (lr=0.001): 1.84      ← lr 提到 0.01 就发散，进退两难
  Adam (lr=0.05): 0.000000  ← 干净利落收敛到谷底
```

Adam 赢在哪？它给每个参数配了**自适应步长**：用梯度的一阶矩（方向）和二阶矩（幅度）分别做动量和归一化——陡峭的 w₂ 方向自动缩小步长，平缓的 w₁ 方向保持推进。SGD 用统一步长面对各向异性损失面，只能小心翼翼。

**实践默认值**：

```text
新任务/新架构     → AdamW, lr=1e-3~3e-4 （几乎不会错）
CV 大规模训练     → SGD+momentum 仍有一战之力（泛化略优的争议存在）
大模型微调        → AdamW + 分层学习率（底层更小）
```

### 概念 4：warmup 与衰减 —— 起步要热身，长跑要变速

真实深度网络的初期梯度又大又乱（随机初始化导致），冷启动大步会直接冲飞。**Warmup**（前 N 步从 0 线性升到目标 lr）模拟实测（初期梯度噪声 σ=50 的场景）：

```text
lr=0.1:  无 warmup 前15步最大误差 16.16 | 有 warmup(30) 8.14
         终点误差              0.51     |          0.15
```

warmup 让网络先「看清地形」再加速。配套的**衰减调度**负责后半程精修：

| 调度       | 形状        | 适用           |
| ---------- | ----------- | -------------- |
| Step decay | 每 N 轮砍半 | 经典 CV 训练   |
| Cosine     | 平滑滑向零  | 当前最流行     |
| 指数衰减   | M4 的 0.5ᵗ  | 简单可靠       |
| One-cycle  | 升-降双相   | 小数据快速训练 |

M4 学的指数衰减公式 `lr(t) = lr₀ × 0.5ᵗ` 在此正式上岗。

### 概念 5：batch size —— 与学习率的跷跷板

```text
小 batch（32/64）：梯度噪声大 → 正则化副作用 + 显存友好 + 更新频繁
大 batch（1024+）：梯度准但探索弱 → 需要更大 lr 配套（线性缩放规则）
```

经验法则：batch 翻 k 倍，lr 可尝试翻 k 倍起步。**两者联动调整，单独拧哪个都可能误判**。显存不够时用梯度累积（DL3 提过的累加语义的正用途）等效放大 batch。

### 概念 6：诊断流程图 —— 训练出问题先查这里

```text
loss 变 nan？          → lr 太大（÷10 重试）→ 数据有 inf/nan → 检查除零/log(0)
loss 不降（水平线）？  → lr 太小或太大 → 检查梯度是否流动（requires_grad/zero_grad）→ 数据管道坏了？
loss 降但 acc 不动？   → 评估代码 bug → 输出层/激活函数选错 → 类别不平衡（ML9）
train 好 test 差？     → 过拟合四件套（ML4）：数据↑ 正则化↓容量 早停 dropout
test 也差且 train 差？  → 欠拟合：加大容量 / 加特征 / 训久一点
时好时坏不稳定？       → 固定随机种子复现 → 多种子取平均看方差（ML9 交叉验证思想）
```

最后一条纪律重申（宪章级）：**每次实验固定随机种子并记录全部超参数**——不可复现的结果等于没做过。

## 自测一下

> [!question]- 1. 你的训练 loss 前几步就冲上天变成 nan。按诊断流程图给出排查顺序。
> 第一嫌疑：**学习率过大**——÷10 或 ÷100 重试（M7 概念 5 的发散现场）。
> 第二嫌疑：**数据脏**——输入含 NaN/inf（未处理的缺失值、log(0)、除零），用断言逐批检查输入张量。
> 第三嫌疑：**数值稳定**——手写 softmax 忘减最大值、log 加 eps 等（DL6 的教训）；若用框架内置函数则排除此项。
> 顺序依据是概率：实践中九成 nan 是 lr 和脏数据这对老搭档。

> [!question]- 2. 为什么「batch size 翻倍就 lr 翻倍」大致成立？这个规则的边界在哪？
> 直觉：大 batch 的梯度是更多样本的平均，方差更小、方向更稳——同样的 lr 下每步可以走得更笃定，因此允许更大的步长；线性缩放规则在小到中等 batch 范围内被大量实验支持。
> 边界：① 极大 batch 时继续线性放大反而伤害泛化（需要 warmup 护航）；② 它是启发式不是定律——换架构/优化器后需重新校验；③ 与自适应优化器（Adam）搭配时关系变弱，因为 Adam 已自带步长归一化。
> 教训：任何「经验法则」都要知道它的适用域，这正是本课把它们排成优先级而非写成铁律的原因。

> [!question]- 3. Adam 几乎总是更快收敛，为什么图像分类竞赛里 SGD+momentum 依然常见？
> 大量实证发现：SGD 找到的解泛化略好于 Adam（差距通常零点几个百分点）。一种解释是 SGD 的均匀步长相当于隐式正则化——它在陡峭方向走得慢反而避开了尖锐极小值（平坦极小值泛化更好的假说）。
> 工程折衷：时间紧/调参少 → AdamW；刷榜冲刺/算力充足 → 两个都试，SGD 赢就用 SGD。另外 AdamW + 合适调度在现代大模型上已是主流，「SGD 泛化优势」主要活跃在中型 CV 任务上。

> [!question]- 4. 「固定随机种子」为什么是纪律级的？举一次不固定种子的具体代价。
> 深度训练处处是随机性：权重初始化、数据 shuffle、dropout 掩码、（GPU 上还有非确定性算子）。不锁种子意味着两次运行结果不同。
> 具体代价：① 你调了一个超参看到提升，重跑一遍提升消失——无法区分真改进还是运气，整个调参过程失去意义；② 论文/报告的数字无法复核；③ 出 bug 时无法回到出错现场调试（DL2 的 XOR 实验就展示过不同种子命运迥异）。
> 一行代码（torch.manual_seed(42) 等）换来整个实验体系的可信度，性价比无出其右。
