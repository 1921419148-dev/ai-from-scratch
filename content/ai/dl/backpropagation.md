## 生活场景切入

公司出了个失误产品。总经理不会冲进车间骂具体工人——流程是这样的：

```text
① 客户投诉到销售 → 销售上报总经理（损失量化）
② 总经理按责任比例追责各总监（误差分摊）
③ 总监再往下追责到每个班组、每个工人（逐层分摊）
④ 每个人根据自己被摊到的责任调整工作方式（参数更新）
```

责任**从结果端倒着流向每个环节**，且每层只管「我该为下游的失误负多少责」。反向传播干的就是这件事：

- **前向传播**：输入流过网络算出预测
- **计算损失**：预测与真相的差距
- **反向传播**：把损失的责任沿链式法则倒着分摊给每个参数
- **更新**：每个参数朝减小自己那份责任的方向挪一步（M7）

## 核心概念拆解

### 概念 1：先复习链条上的两个零件

反向传播 = 链式法则（M6）的系统化执行。需要的零件全部就位：

```text
前向（M3 复合函数）：   x → [层1] → h → [层2] → ŷ → L(ŷ, y)
链式法则（M6）：        ∂L/∂w₁ = ∂L/∂ŷ × ∂ŷ/∂h × ∂h/∂w₁
梯度下降（M7）：        w₁ ← w₁ − η · ∂L/∂w₁
```

唯一的新知识是**工程化**：当网络有几十层、百万参数时，「对每个参数分别求导」太笨了。反向传播的聪明之处是一次倒序遍历，顺便把所有参数的梯度全部算出——代价只有一次前向传播的两倍左右。

### 概念 2：手推一遍最小网络 —— 梯度长什么样

用最小的网络（1 输入 → 2 隐藏 → 1 输出）走全流程。设定 `x=1.5, t=1.0`，sigmoid 隐藏层 + sigmoid 输出 + 平方损失（以下数值均为实际计算结果）：

```python
import math

def sigmoid(z): return 1/(1+math.exp(-z))

W1=[0.5,-0.3]; b1=[0.1,0.2]; W2=[0.8,-0.6]; b2=0.05
x, t = 1.5, 1.0

# ---- 前向传播 ----
h_pre = [W1[j]*x + b1[j] for j in range(2)]        # 隐藏层加权输入
h     = [sigmoid(v) for v in h_pre]                # 隐藏层输出 [0.7006, 0.4378]
o     = sigmoid(sum(W2[j]*h[j] for j in range(2)) + b2)   # 0.5861
loss  = (o - t)**2                                  # 0.1713

# ---- 反向传播 ----
d_o  = 2*(o - t)*o*(1 - o)          # 输出层误差信号（损失导数×激活导数）
db2  = d_o                          # b2 在加法末端，原样接收
dW2  = [d_o*h[j] for j in range(2)] # W2 的梯度 = 误差 × 上游激活值
dh   = [d_o*W2[j]*h[j]*(1-h[j]) for j in range(2)]  # 责任继续往上游传
dW1  = [dh[j]*x for j in range(2)]
db1  = dh

print("dW2 =", [round(v,7) for v in dW2])   # [-0.1406946, -0.0879279]
print("dW1 =", [round(v,7) for v in dW1])   # [-0.0505543, 0.0444879]
```

读出三个规律（所有框架的反向传播都长这样）：

1. **每层的误差信号 = 下游传来的责任 × 本层激活函数的局部导数**
2. **权重的梯度 = 流经本层的误差信号 × 送入该权重的上游激活值**（`dW2 = δ·h`）
3. 责任传过一层就要乘一次权重和局部导数——层数一多连乘变小，这正是 DL1 预告的**梯度消失**根源

### 概念 3：数值梯度 —— 用笨办法验证聪明办法

手推的公式对不对？有个万能检验法：**数值梯度**——直接用定义 `(L(w+ε) − L(w−ε))/2ε` 硬算（中心差分）。它慢得没法用于训练，但做「考官」完美：

```python
eps = 1e-7

def loss_at(W1v, W2v):
    h_pre = [W1v[j]*x + b1[j] for j in range(2)]
    h = [sigmoid(v) for v in h_pre]
    o = sigmoid(sum(W2v[j]*h[j] for j in range(2)) + b2)
    return (o - t)**2, h, o

l2, _, _ = loss_at([W1[0]+eps, W1[1]], W2)
num_dW1_0 = (l2 - loss) / eps

print(num_dW1_0)      # -0.0505543 —— 与解析解 dW1[0] 完全一致 ✓
```

实测对比：`dW1 解析 [-0.0505543, 0.0444879]` vs `数值 [-0.0505543, 0.0444879]`——**小数点后七位一致**。（调试花絮：最初推导时漏乘了上游输入 x，数值检验立刻抓出差了 1.5 倍——正是 x=1.5。这就是梯度检查的价值：**链式法则哪里断了你未必看得出来，但数字不会说谎**。深度学习框架内部也内置这套机制。）

### 概念 4：亲手解开 XOR 死局

DL1 留下的悬念现在揭晓：给单层加上一个隐藏层（2→4→1），用上面的反向传播训练 20000 轮（实际运行结果）：

```python
# 结构：2 输入 → 4 隐藏(sigmoid) → 1 输出(sigmoid)，lr=1.5
# 训练代码即概念 2 的流程套上循环，完整版约 40 行纯 Python

训练后:
  [0, 0] → 0.0055  (target 0) ✓
  [0, 1] → 0.9945  (target 1) ✓
  [1, 0] → 0.9945  (target 1) ✓
  [1, 1] → 0.0069  (target 0) ✓
四舍五入: [0, 1, 1, 0] —— XOR 完美攻克！
```

1969 年宣判「不可能」的问题，仅仅因为**多了一层非线性弯折**就被解决了。隐藏层的四个神经元各自学会了在平面上画一条折线，输出层再把四条折线围出的区域判为 1——两次线性切割的组合构成了弯曲的边界。

> [!note] 工程诚实声明
> 这个演示同时暴露了神经网络的另一面：换一组随机种子或学习率，XOR 有时收敛到 0.49 的「骑墙解」（卡在鞍点附近）。小网络的训练对初始化相当敏感——这也是为什么实践中要用 DL12 讲的初始化技巧和多次重启。

### 概念 5：训练循环的全景图

把一切组装成你今后到处都会见到的伪代码骨架：

```text
for epoch in 轮次:
    for batch in 切好的小批数据:
        ŷ = forward(x_batch)          # 前向：算预测
        L = loss(ŷ, y_batch)          # 打分
        grad = backward(L)            # 反向：链式法则分摊责任
        w ← w − η·grad               # 更新：梯度下降走一步
    if 验证集损失不再下降: 早停       # ML4 的纪律
```

PyTorch 里这四行对应 `model(x)` / `criterion(...)` / `loss.backward()` / `optimizer.step()`——DL3 就去认识它们。**你已经理解了这四个调用背后发生的每一件事**，这是很多调包侠一辈子没补上的课。

## 自测一下

> [!question]- 1. 为什么说反向传播是「链式法则的高效实现」而不是新数学？
> 对每个参数直接套链式法则求导，会有大量重复计算（同一中间量的导数被反复求）。反向传播把它重排成**一次倒序遍历**：从损失出发，每层只算一次自己的局部量并向上游传递，所有参数的梯度顺路全部得出。
> 这是动态规划思想（子结果复用）：时间复杂度从天文数字降到约为前向传播两倍。数学没有新东西，工程组织天才。

> [!question]- 2. 权重的梯度公式 `dW2 = δ · h` 中，δ 是什么、h 是什么？为什么是这个乘积形式？
> δ 是流经该层的误差信号（损失对本层输出的导数），h 是送入这个权重的上游激活值。
> 来源是复合函数求导：损失依赖 o=σ(W2·h)，对 W2[j] 求导时，链式法则给出「外层导数 dL/do（含在 δ 里）× 内层导数 do/dW2[j] = σ'(...)·h[j]」——sigmoid 局部导数并入 δ 后恰好剩下 h[j]。
> 记忆口诀：**梯度 = 流过的电流 × 送电的闸门开度**。

> [!question]- 3. 数值梯度检查为什么要用中心差分 `(L(w+ε)−L(w−ε))/2ε` 而不是单侧 `(L(w+ε)−L(w))/ε`？
> 单侧差分的截断误差是 O(ε)，中心差分两侧相减把一阶项抵消，截断误差降到 O(ε²)——同样的小 ε 下精度高一个数量级。
> 但 ε 也不能太小：浮点减法在大数之间会丢失精度（灾难性消去），所以实践取 ε≈1e-5~1e-7 并要求相对误差 < 1e-6 左右才判定「通过」。这种「理论误差与浮点误差打架」的权衡是数值计算的日常。

> [!question]- 4. XOR 实验中，同样的代码有时训出完美答案有时卡在 0.49。卡住的原因最可能是什么？两种工程对策？
> 最可能卡在**鞍点或糟糕的初始区域**：四个样本对称，某些初始化下正负梯度互相抵消，网络停在输出 0.5 附近的平衡点上动弹不得。
> 对策：① **多次随机重启**——换个种子重新初始化再训，工业界最朴素有效；② **改进初始化与优化器**——如 Xavier/He 初始化打破对称性、带动量的 SGD 或 Adam 帮助冲过平原（DL12 展开）。此外增大隐藏单元数也能降低陷入坏区域的概率。
