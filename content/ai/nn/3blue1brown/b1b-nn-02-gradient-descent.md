## 🗺 先拿地图

```mermaid

    A["训练数据<br/>几万张标好答案的图"] --> B["损失函数<br/>把『答得有多差』<br/>变成一个数"]
    B --> C["梯度<br/>告诉每个参数：<br/>往哪边动能让损失变小"]
    C --> D["更新参数<br/>挪一小步"]
    D --> B
```

视频的推进逻辑：

1. **先泼冷水**：第 1 集的网络结构是随便设的，权重偏置全是随机数。随机初始化的网络识别数字，正确率约等于瞎猜。
2. **定义「差劲」**：损失函数把「10 个输出激活值 vs 正确答案」折算成一个非负数。损失越大 = 错得越离谱。
3. **关键转场**：把全部几万个权重和偏置看作一个**超高维空间里的一个点**。损失函数在这个空间上造出一片「地形」，学习 = 找下坡路。
4. **梯度登场**：梯度指向「上坡最陡」的方向，那**负梯度**就是「下坡最陡」。反复「看坡度 → 迈小步」，就是梯度下降。

## 🧠 核心概念拆解

### 概念 1：损失函数 = 考试扣分器

对一张训练图，把网络输出和正确答案逐项比较（视频用的是平方误差思路），加起来得到一个数：

$$C = \sum_{i}(\text{激活值}_i - \text{目标}_i)^2$$

用人话：「你输出的 10 个数字」和「标准姿势 0100000000」差多远？只对**一张图**算出来的叫单个样本的损失；对**几万张图**取平均，才是要最小化的总损失。

> [!important] 为什么必须是个连续可导的函数？
> 因为后面要对它求斜率。如果「答错就记 1 分、答对记 0 分」，分数会跳来跳去，你看不出「往哪边微调能变好一点」。**平滑**是能「学习」的前提。

### 概念 2：13000 维空间（视频原话）

MNIST 例子里约 1.3 万个参数 → 损失地形是 13002 维的空间（参数 + 高度）。我们画不出它，但一维直觉完全够用：

- 站在山坡某处（当前参数）
- 感受脚下坡度（梯度）
- 朝下坡迈一步（更新参数）
- 反复，直到几乎平了（收敛）

### 概念 3：学习率——步子多大？

负梯度给出**方向**，走**多远**由学习率（Learning Rate）决定：

- 太大 → 每步冲过谷底来回震荡甚至发散
- 太小 → 收敛极慢，训练磨洋工
- 刚好 → 稳步下滑到谷底附近

这就是为什么所有深度学习工程师都在调这个旋钮。

### 概念 4：随机梯度下降 SGD

几万张图全算一遍太慢，实际操作是**每次随机抽一小批**（mini-batch）估计坡度就开走。方向偶尔歪，但平均是对的——快得多。现代框架里你看到的 `optimizer.step()` 干的就是这件事。

实验任务清单：

## ✅ 自测一下

> [!question]- 1. 损失函数的输入和输出分别是什么？
> 输入：当前全部参数（权重+偏置）+ 训练数据决定的输出表现；本质上是「当前这组参数在训练集上答得有多差」。输出：一个非负数，越大越差。训练目标就是让它尽量小。

> [!question]- 2. 为什么沿着「负梯度」方向移动？
> 梯度指向函数上升最快的方向；取反就是下降最快方向。想减小损失，当然朝下降最快的方向走。（类比：蒙住眼睛下山，用脚感受哪边最陡往下，就往那边迈。）

> [!question]- 3. 学习率设得过大会发生什么？
> 每步跨过谷底到对面更高处，损失不降反升、来回震荡甚至指数级发散——演示里的小球直接飞出画面。工程上的症状是训练 loss 变成 NaN 或剧烈抖动。

> [!question]- 4. SGD 的「随机」体现在哪里？为什么反而更快？
> 每轮不用全部训练数据算梯度，而是随机抽一小批。单批方向有噪声，但期望方向仍指向下坡；计算量却缩小了几十倍，单位时间走的步数多得多——综合下来更快接近谷底。
