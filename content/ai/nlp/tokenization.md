> [!abstract] 本课将学到
>
> - **分词（Tokenization）**：把文本切成模型能消化的最小单位
> - **One-Hot 编码**：最朴素的词表示，以及它为什么撑不住真实词表
> - **词袋模型（Bag of Words）**：只数个数不管顺序——有用但有硬伤
> - 中文分词的特殊难题
> - 这些缺陷正是 NLP2 词向量登场的理由

## 生活场景切入

神经网络只会算数字（DL1 的第一课就说过）。可「我今天很开心」是五个汉字，不是五个数字。

NLP 的第一步永远是把文字翻译成数字。听起来简单，做起来处处是坑：

```text
英文好办：空格天然分词  → "I love NLP" → [I] [love] [NLP]
中文头疼：「我爱自然语言处理」→ 我 / 爱 / 自然 / 语言 / 处理？
                                还是 我爱 / 自然 / 语言 / 处理？
```

切错了，后面全错。这一课就把「切」和「表示」两件事讲透。

## 核心概念拆解

### 概念 1：Tokenization —— 切多细是个哲学问题

三种粒度各有拥趷：

| 粒度     | 例子                        | 词表大小 | 缺点                 |
| -------- | --------------------------- | -------- | -------------------- |
| 字符级   | 我/爱/自/然/语/言           | 很小     | 单字无义，序列超长   |
| 词级     | 我/爱/自然语言/处理         | 巨大     | 新词（OOV）直接抓瞎  |
| 子词级 ★ | unbreakable → un/break/able | 可控     | 现代大模型的标准答案 |

现代模型的答案叫 **BPE（Byte Pair Encoding）**：从字符开始，反复合并语料中最常见的相邻对，直到达到目标词表大小。「unhappiness」没见过？拆成「un + happi + ness」，三个零件都是熟脸。**子词让词表有限而表达力无限**——GPT 系列的 token 就是这么来的。

中文的额外难点：没有空格提示边界。「南京市长江大桥」可以切成「南京市 / 长江大桥」（一座桥）或「南京市长 / 江大桥」（一位领导）——歧义需要语义才能裁决，这也是为什么中文分词曾是独立的研究领域。

### 概念 2：One-Hot —— 每个词一根独苗

最直白的表示：词表多大，向量就多长；自己的位置是 1，其余全是 0：

```python
text = "我爱自然语言处理"
tokens = list(text)                       # 教学演示按字切
vocab = sorted(set(tokens))               # 词表 ['处','我','然','爱','理','自','言','语']

onehot_ai = [1 if w=="爱" else 0 for w in vocab]
print(f"『爱』的 one-hot: {onehot_ai}")   # [0, 0, 0, 1, 0, 0, 0, 0]
```

两大死穴：

1. **维度灾难**：真实词表几十万，每个词是一根几十万维的独苗——稀疏到浪费
2. **词与词零相关**：one-hot 下「猫」和「狗」的内积为 0，「猫」和「混凝土」的内积也是 0——**语义信息完全丢失**

第二个问题才是真正的绝症：任何基于 one-hot 的模型都无法理解「猫和狗都是动物」。出路只有一个——用**稠密的、带语义的向量**代替独苗。这就是下一课的主角。

### 概念 3：词袋模型 —— 只数个数不看顺序

文档级表示的经典方案：把句子装进「袋子」，只记录每个词出现几次：

```python
def bow(sent):
    words = sent.split()
    return {w: words.count(w) for w in set(words)}

s1 = "这部电影 太 好看 了"
s2 = "这部 电视剧 真的 好看"
b1, b2 = bow(s1), bow(s2)
# 共同词「好看」「太」贡献相似度；实测余弦相似度 = 0.25
# 而 s1 与无关句子的相似度 = 0.000 ✓ 方向正确
```

词袋 + TF-IDF 权重 + 朴素贝叶斯/线性分类器 = 一套至今活跃在工业界垃圾过滤、初筛任务的经典组合拳（NLP3 实战）。

但词袋有个天生残缺——实测一秒钟打脸：

```python
bow("猫 咬 狗") == bow("狗 咬 猫")    # True！完全相同的表示
```

**顺序信息全部丢失**。语言的意义恰恰大量藏在顺序里：「我不喜欢它」和「我喜欢不它？」、「狗咬人」和「人咬狗」。词袋看不见这些差别。

### 概念 4：n-gram —— 给词袋补一点顺序

补救方案：不止数单词，还数相邻的 n 个词组合（bigram 二元组、trigram 三元组）：

```text
「不喜欢」作为 bigram 是一个整体单元 → 「不」+「喜欢」的反转得以保留
```

代价是组合爆炸：5 万词表的三元组空间是 125 万亿。实践中靠截断（只保留高频 n-gram）续命。这条思路走到头，人们意识到需要一个**能自动学习顺序特征的稠密表示**——历史的车轮推向了神经网络 NLP（NLP2 起）。

## 自测一下

> [!question]- 1. 为什么说「词级分词的 OOV 问题」在 BPE 出现后基本解决？
> 词级方案遇到新词只能报错或丢弃；BPE 把一切未知词降解成已知的子词零件——「ChatGPTization」这种生造词也能拆成 Chat/GPT/ization 三块熟料。
> 本质转变：词表从「枚举所有完整词」改为「枚举所有高频零件」，有限零件组合出无限词汇。这是工程上「用组合对抗枚举」的又一胜利，与 M1 科学计数法、DL6 softmax 多类化的思想同源。

> [!question]- 2. 「猫咬狗」和「狗咬猫」词袋相同——请举一个这种丢失会造成实际业务事故的例子。
> 舆情监控场景：评论「商家欺骗消费者」与「消费者误解了商家」若用词袋表示几乎同分布（共享「商家」「消费者」等词），情感分类器可能给出相近的分数。
> 但前者该触发危机预警，后者是普通客服回复——方向完全相反。医疗、法律文本里「A 感染 B」vs「B 感染 A」更是性命攸关。凡是谓语方向决定含义的场景，词袋都不可单独信任。

> [!question]- 3. 中文的「南京市长江大桥」歧义为什么难自动消解？给出两种可行的消解依据。
> 因为两种切法在字面上都合法，歧义必须由字面之外的知识裁决：
> ① **统计依据**：大规模语料中「长江大桥」共现频率远高于「江大桥」，按最大概率路径选前者；
> ② **语境依据**：上下文出现「通车/桥墩」走桥义，出现「履新/调任」走人名义。
> 现代预训练模型的优势正在于把这两种知识都吸收进了参数里——这也是分词器从「规则工程」演进到「模型内生」的历史脉络。

> [!question]- 4. one-hot 向量的内积恒为零意味着什么？这个性质如何直接引出词向量的设计目标？
> 任意两个不同词的 one-hot 内积都是 0——模型眼中的所有词彼此正交、毫无关系，等价于一张「每个词都是孤岛」的世界地图。
> 词向量的设计目标由此反推得出：找一个低维稠密空间，让**语义相近的词几何上相邻**（内积/余弦大）。「猫」和「狗」应该靠近，「猫」和「混凝土」应该远离——把语言学知识翻译成几何约束，这正是 NLP2 的全部剧情。
