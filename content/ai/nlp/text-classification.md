## 生活场景切入

电商平台每天涌入百万条评论，人工看不过来。需求很朴素：

```text
输入：「太好看了，值回票价！」     → 输出：好评 ✅
输入：「难看，浪费时间和金钱」     → 输出：差评 ❌
```

这就是**情感分析（Sentiment Analysis）**——文本分类最经典的应用。好消息是它不需要大模型：一条 1950 年代的老算法配上几十条样本就能起步，本课全程纯 Python、零依赖。

## 核心概念拆解

### 概念 1：任务定义与数据

```text
任务：二分类（好评 / 差评）
数据：16 条短影评（8 正 8 负），每条已空格分词
评估：先看训练集自测，再打新样本
```

教学版数据刻意极小——为了让你看清算法的每一根血管；真实项目换成万条语料，代码一行不用改。

### 概念 2：朴素贝叶斯 —— 用贝叶斯定理数单词

ML9 学过贝叶斯定理（证据更新信念）。把它用在文本上：

```text
P(好评 | 文档) ∝ P(好评) × P(词1|好评) × P(词2|好评) × …
```

逐项解读：

- `P(好评)`：**先验**——训练集里好评占比（8/16 = 0.5）
- `P(词|好评)`：**似然**——在好评文档里见到这个词的频率
- 中间全是乘号：**朴素假设**——词与词出现与否相互独立（这就是名字里「朴素」的由来；语言显然不独立，但工程效果意外地好）

预测时算两个类别的后验，谁大听谁的。

### 概念 3：拉普拉斯平滑 —— 救命的小常数

致命细节：测试句「剧情 精彩」里的「剧情」如果没在任何好评里出现过，`P(剧情|好评) = 0`，整个乘积瞬间归零——**一个没见过的词就否决全部其他证据**，显然荒谬。

解法是给所有计数加 1（拉普拉斯平滑）：

```text
P(w|好评) = (好评中 w 的次数 + 1) / (好评总词数 + 词表大小)
```

没见过的词拿到一个小而非零的概率——「没见过 ≠ 不可能」。这个一行的修改让模型对开放世界的鲁棒性质变。

### 概念 4：完整实战 —— 20 行纯 Python

```python
import math

pos_reviews = ["好看 极了 强烈 推荐", "剧情 精彩 演员 出色", "太 好看 了 值回票价",
               "感动 温暖 好片", "精彩 绝伦 推荐", "很 好看 喜欢",
               "出色 的 作品", "推荐 大家 去 看"]
neg_reviews = ["难看 浪费 时间", "剧情 混乱 差评", "太 难看 了 后悔",
               "尴尬 无聊 烂片", "失望 别 看", "演技 尴尬 剧情 拉 胯",
               "烂片 警告", "不 推荐 太 差"]

# ① 数词频
vocab = set(); counts = {"pos": {}, "neg": {}}
for doc, label in [(d, "pos") for d in pos_reviews] + [(d, "neg") for d in neg_reviews]:
    for w in doc.split():
        vocab.add(w); counts[label][w] = counts[label].get(w, 0) + 1
total_pos, total_neg = sum(counts["pos"].values()), sum(counts["neg"].values())
V = len(vocab)

def score(doc):
    sp = math.log(len(pos_reviews)/(len(pos_reviews)+len(neg_reviews)))
    sn = math.log(1 - len(pos_reviews)/(len(pos_reviews)+len(neg_reviews)))
    for w in doc.split():
        sp += math.log((counts["pos"].get(w, 0)+1)/(total_pos+V))   # +1 平滑
        sn += math.log((counts["neg"].get(w, 0)+1)/(total_neg+V))
    return sp, sn

# ② 打新样本
tests = ["好看 又 感动 的 好片", "浪费 时间 的 烂片", "剧情 精彩", "无聊 尴尬"]
for t in tests:
    sp, sn = score(t)
    print(f"『{t}』→ {'好评' if sp > sn else '差评'}")
```

实际运行结果：

```text
『好看 又 感动 的 好片』→ 好评   (logP差 = +3.39)
『浪费 时间 的 烂片』  → 差评   (logP差 = −1.85)
『剧情 精彩』          → 好评   (logP差 = +0.66)
『无聊 尴尬』          → 差评   (logP差 = −1.82)
训练集自测：16/16 全对
```

注意两个细节：① 「剧情」同时出现在正负样本里，靠两侧频率差裁决（+0.66 是险胜）；② 为什么取 log？连乘几十个小数会下溢到 0（M4 学过的下溢问题），取对数把乘法变加法——数学与工程在此再次合流。

### 概念 5：这套方法的边界

诚实盘点朴素贝叶斯+词袋的天花板：

```text
✅ 能胜任：主题分类、垃圾过滤、粗粒度情感
⚠️ 会翻车：
   否定反转 → 「不难看」（词袋只见「不」「难看」，负词误伤）
   反讽挖苦 → 「真是太'精彩'了，我睡着了」（字面正面实际负面）
   复杂句法 → 长距离依赖完全无感（NLP1 词袋缺陷的全部继承）
```

突破天花板需要理解上下文的模型——RNN/BERT/GPT 的进化路线（NLP6/NLP7）。但请记住工程铁律：**先用最简单的基线跑通全流程**，朴素贝叶斯常常是那个性价比惊人的第一版。

## 自测一下

> [!question]- 1. 「朴素」假设明明违背语言学常识（词与词强相关），为什么朴素贝叶斯还能用？
> 因为它要的是**分类决策正确**，不是概率估计精确。词相关性的违反会把绝对概率估歪，但只要歪的方向在两个类别间大体一致，argmax 的胜负就常不受影响。
> 类比：考试不需要算出物理量的精确值，只需要选项比大小。当然，当你需要校准的概率输出时（如风控定价），朴素假设的失真就必须认真对待了。

> [!question]- 2. 把拉普拉斯平滑的 +1 改成 +100 会发生什么？
> 平滑强度过大：罕见词的证据被严重稀释，词频差异被抹平——「烂片」和「片」在差评模型里的区分度大幅下降，模型趋向于只信先验。
> 极端时所有 P(w|类) 都趋近均匀分布，分类器退化成「永远猜多数类」。平滑系数本身是个超参数（α=1 只是默认值），可用 ML9 的交叉验证调优。

> [!question]- 3. 为什么计算中要全程使用对数概率？写出具体的技术原因。
> 一篇文档有几十个词，每个 P(w|类) 都是小于 1 的数。50 个 0.01 相乘 = 10⁻¹⁰⁰，远低于双精度浮点的表示下限（约 10⁻³⁰⁸）——直接连乘会下溢归零，且无法区分「特别不可能」和「程序出错」。
> 取对数后连乘变累加（−100 是个健康的小数字），既保精度又提速（加法快于乘法）。这条技巧与 M4 交叉熵、NLP7 语言模型的 loss 同源——**对数空间是概率机器学习的母语**。

> [!question]- 4. 老板要求你的情感分析器上线后准确率 ≥90%，但你只有 200 条标注。给出三步走方案。
> ① **立刻**：朴素贝叶斯/线性 SVM + TF-IDF 跑通基线（今天的内容，半小时），确认流程与数据质量；
> ② **短期**：换预训练模型微调（DL10 范式）——中文可用现成的 BERT 变体，200 条足够微调出 90%+ 的细粒度情感能力，标注预算优先扩到 1000~2000 条；
> ③ **长期**：上线后用「模型不确定的低置信样本」回流给人工标注（主动学习），形成数据飞轮。
> 思想主线：简单基线定底线 → 迁移学习提上限 → 数据飞轮滚雪球——三个板块的知识在这里合流。
