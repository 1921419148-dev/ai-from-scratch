## 生活场景切入

2018 年，几乎所有人的目光都聚焦在 BERT 的刷榜狂欢上。OpenAI 默默发布的 GPT-1 看起来像个配角：参数只有 BERT-large 的四分之一，成绩也不如。

但 OpenAI 信奉另一条朴素到近乎固执的路线：**不做任何任务特化，只做一件事——预测下一个词，然后把这个做到极致**。GPT-2（15 倍大）开始写出像模像样的文章；GPT-3（1750 亿）展示 in-context learning；ChatGPT 补上对话对齐——2022 年底，世界突然发现：那条被当作配角的路线，已经通向了通用智能的门。

## 核心概念拆解

### 概念 1：三部曲的进化阶梯

| 型号  | 年份 | 参数 | 关键证明                                      |
| ----- | ---- | ---- | --------------------------------------------- |
| GPT-1 | 2018 | 117M | 「生成式预训练+判别微调」可行，与 BERT 同期   |
| GPT-2 | 2019 | 1.5B | 不微调也能零样本做多种任务；文本以假乱真      |
| GPT-3 | 2020 | 175B | **in-context learning**：给几个例子就会新任务 |

注意曲线形状：每代之间是纯粹的规模放大（DL11 的幂律），架构改动极小。**GPT 家族的胜利本质上是 Scaling Laws 的胜利**——先有信念（OpenAI 2019 年论文标题就是《Language Models are Few-Shot Learners》），再用算力兑现信念。

### 概念 2：自回归生成 —— 一个词一个词地吐

GPT 生成文本的方式是严格串行的：

```text
输入「今天天气」→ 模型给出下一个词分布 → 采样「很」
当前「今天天气很」→ 分布 → 采样「好」
当前「今天天气很好」→ ……
直到采样出结束符或达到长度上限
```

每一步的输出拼回输入再进模型——**自己的输出变成自己的输入**，故名自回归（autoregressive）。这个机制决定了大模型的所有使用体感：

- 为什么逐字蹦出来（流式输出的技术根源）
- 为什么问它字数会数错（它不知道自己还没写完的字数）
- 为什么同样的提示两次回答不同（有采样的随机性，见下）

### 概念 3：Temperature 与 Top-p —— 随机性调节旋钮

每一步模型给出的不是确定的词，而是整个词表的概率分布。怎么从中挑词？两个旋钮控制风格（用玩具 bigram 语料实测，实际运行结果）：

```python
# 语料：「今天天气不错心情也好。今天天气很差…明天天气应该不错。」
# 任务：从「今天」续写 5 个词

低温 T=0.3（保守）：三次运行高度雷同
  '今天 天气 不错 心情 也 好' / '今天 天气 可能 很 差 心情' / '今天 天气 应该 不错 心情 不'

原温 T=1.0（本色）：出现更多样组合
  '今天 天气 不错 。 明天 天气' / '今天 天气 应该 不错 心情 不' …

高温 T=1.6（放飞）：分布被拉平，低概率词也常被选中，语无伦次风险上升

贪心(T→0)：永远输出 '今天 天气 不错 心情 也 好' —— 最稳也最无聊
```

| 旋钮        | 调低的效果                          | 调高的效果                           | 典型用法             |
| ----------- | ----------------------------------- | ------------------------------------ | -------------------- |
| Temperature | 分布尖锐化，更确定                  | 分布拉平，更有创意                   | 写代码用低，写诗调高 |
| Top-p       | 只保留累计概率 p 内的候选，砍掉长尾 | 同左（作用类似温度但按概率质量截断） | 抑制胡言乱语         |

工程口诀：**要准确选低温/贪心，要创意加高温；胡说八道就收 top-p**。这两个旋钮后来成为所有大模型 API 的标准配置。

### 概念 4：「预测下一词」为什么能逼出智能 —— 任务哲学的正名

这是本课最重要的一节思想课。直觉上，「补全文字」只是鹦鹉学舌。但把任务难度想透：

```text
要可靠地预测「水的化学式是 H₂__」的下一个 token
→ 必须在参数里存储化学知识

要预测「小明比小红高，小红比小刚高，所以最高的是__」
→ 必须执行推理

要预测一个好笑的段子结尾
→ 必须建模幽默感与预期违背
```

互联网级文本里的下一词预测，隐含着对**几乎所有人类知识的压缩与重组**。任务越简单纯粹，可用的数据就越多（无需标注）；规模上去后，简单任务反而榨出了最丰富的能力——这与 NLP2 词向量「伪装任务偷学语义」是同一哲学的两次伟大实践，中间隔了整整七年和五个数量级的算力。

### 概念 5：从 GPT 到 ChatGPT —— 还缺的最后一块

纯 GPT-3 有个致命缺陷：它是台「文档续写机」，你问它问题，它可能给你续写出一串相似的问题而非答案。

ChatGPT 的最后一块拼图是**对齐训练**：指令微调（教它「用户说话时要回应」）+ RLHF（用人类偏好校准它的行为）。这一步不改「预测下一词」的底座，只是让它学会扮演一个乐于助人的助手角色。技术细节属于强化学习板块的 RLHF 一课——NLP 板块的故事线到此交棒。

## 自测一下

> [!question]- 1. GPT-3 的 in-context learning 与传统微调的本质区别是什么？
> 微调改变**参数**（梯度下降更新权重，需要训练管线与数据）；ICL 改变的只是**输入**（几个示例放进提示词，权重一个不动）。
> 这意味着「学习」发生在单次前向传播内部——模型临时从上下文中提取模式完成任务。代价是每次都要携带示例（token 计费），收益是零成本切换任务。DL10 的预训练-微调范式在此长出了第三条腿：预训练、微调、上下文学习各司其职。

> [!question]- 2. 为什么写代码场景建议 temperature 调很低，而写营销文案建议调高？从分布角度解释。
> 代码的正确解空间极窄：语法必须合法、API 名不能编造——分布中高质量区域集中，采样波动只会引入 bug，低温让模型始终落在最可信的词上。
> 文案的优质解空间宽阔（同一卖点多重表达皆可），且过度确定性会产生千篇一律的模板腔——适度高温扩大探索面，让低概率的好词也有出场机会。
> 本质：**任务的容错率决定随机性的预算**——这同样是 ML9「指标匹配业务」思想的镜像。

> [!question]- 3. 「预测下一词这么简单的任务不可能产生真正的理解」——给出两条反驳。
> 反驳一（信息论视角）：互联网文本的下一词包含着对世界状态的高压缩编码。要预测「水的沸点是100摄\_\_\_」，没有物理知识寸步难行；任务表面简单，做好它的充分条件深不见底。
> 反驳二（实证视角）：探针实验显示大模型的内部表征线性可解码出事实、情感乃至推理步骤；跨任务迁移、few-shot 泛化的表现也无法用「死记硬背」解释。
> （诚实的补充：反方关于「统计鹦鹉」的论证亦有严肃版本——理解与模拟理解的哲学边界至今未决。重要的是双方都在用可检验的证据说话。）

> [!question]- 4. 把 GPT-1→GPT-3 的路线与 BERT 的路线放在一起，为什么最终 GPT 式胜出？给出至少两条结构性原因。
> ① **目标函数的通用性**：预测下一词天然兼容一切文本形态（问答/翻译/代码都是「续写」的特例），BERT 的完形填空则偏向理解类；生成时代到来后 decoder 占尽先机。
> ② **数据效率的天花板**：两者都用自监督，但 next-token 可利用的数据形式无约束（任何连贯文本），MLM 需精心设计掩码策略。
> ③ **Scaling 兼容性**：decoder-only 结构简洁（单塔堆叠），对 DL11 的规模游戏最友好。
> 当然胜者书写历史也有幸存者偏差成分——encoder 系在理解类细分市场依然活得很好（NLP6 已述）。
