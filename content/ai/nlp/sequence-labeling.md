## 生活场景切入

读一遍这句话，注意你大脑自动完成的事情：

> 「**张三**在**北京大学**读书，毕业后进了**腾讯公司**。」

你瞬间识别出张三是人名、北京大学和腾讯公司是机构——尽管「大学」本身不是机构、「腾讯」单独出现也未必是。这种从文本中挖出**结构化信息**的能力，正是搜索引擎知识图谱、金融风控、医疗病历结构化的底层技术。

任务形式化：给句子里的每个字打标签——这就是**序列标注**。

## 核心概念拆解

### 概念 1：为什么不是普通分类 —— BIO 体系的诞生

对每个词独立分类不够用：「北」「京」「大」「学」四个字单看都只是普通名词。需要一种能表达**边界与归属**的记号，业界标准是 BIO：

```text
B-X  Begin    实体的第一个字
I-X  Inside   实体的后续部分
O    Outside  非实体

例句: 张  三  在  北  京  大  学  读  书
标签: B-PER I-PER O B-ORG I-ORG I-ORG O O
```

三条精妙之处：

1. `B` 与 `I` 的接力天然编码了**边界**：「B-PER I-PER」= 两字人名
2. `I` 必须紧跟同类型的 `B/I`——非法转移（如 O 后直接接 I）可被约束排除
3. 换个标签集就能做分块/词性/分句——**一套记号服务整个任务家族**

### 概念 2：亲手解码 BIO

给定模型的输出标签序列，把实体拼回来（实际运行结果）：

```python
sentence = ["张", "三", "在", "北京", "大学", "读书"]
bio      = ["B-PER", "I-PER", "O", "B-ORG", "I-ORG", "O"]

def extract_entities(tokens, tags):
    ents, cur = [], None
    for tok, tag in zip(tokens, tags):
        if tag.startswith("B-"):
            if cur: ents.append(cur)
            cur = [tag[2:], tok]
        elif tag.startswith("I-") and cur and tag[2:] == cur[0]:
            cur[1] += tok
        else:
            if cur: ents.append(cur); cur = None
    if cur: ents.append(cur)
    return [(t, e) for t, e in ents]

print(extract_entities(sentence, bio))
# [('PER', '张三'), ('ORG', '北京大学')]   ✓ 两个实体干净抽出
```

解码逻辑就是一台小状态机：见 B 开新账本、见同类 I 续写、见其他落袋归档。

### 概念 3：路线一 —— 规则/词典法

最古老的方案：维护一份后缀词典 + 前向扫描（实际运行结果）：

```python
# 规则：遇到「大学/公司/银行」等后缀就往前抓候选字符
rule_ner("他在清华大学读书，毕业后进了腾讯公司")
# 输出含 ('在清华大学', 'ORG') 和 ('了腾讯公司', 'ORG')
```

看输出就暴露问题：抓进了「在」「了」这些无关前缀——纯规则的边界判断很粗糙。但规则法的优势同样真实：

| 维度     | 规则/词典法        | 模型法         |
| -------- | ------------------ | -------------- |
| 冷启动   | 无需标注数据       | 需要数千条标注 |
| 精确率   | 高（词典内必正确） | 取决于数据     |
| 召回率   | 低（词典外全瞎）   | 高             |
| 可控性   | 改规则立竿见影     | 要重训练       |
| 维护成本 | 词表爆炸式膨胀     | 相对稳定       |

工业界常用**混合策略**：模型打主力 + 领域词典兜底关键实体（药品名、产品型号等不容出错的）。

### 概念 4：路线二 —— 模型怎么学序列标注

现代 NER 的标准配方：

```text
预训练模型（BERT 等）给每个字算上下文向量     ← 解决一词多义
       ↓
序列标注层预测每个字的 BIO 标签分布            ← 普通分类头即可
       ↓
（可选）CRF 层约束标签合法性                   ← 排除 O→I 这类非法转移
```

三个组件各司其职。BERT 的上下文能力解决了经典难题：「苹果发布了手机」里「苹果」不会被判成水果；CRF 的转移矩阵让「I-ORG 出现在句首」这种结构性错误直接不可能发生。深度学习时代 NER 在标准数据集上 F1 已达 95%+，远超任何人工词表的天花板。

### 概念 5：序列标注家族 —— 一通百通

同一套 BIO/模型骨架换个标签集就是新任务：

| 任务         | 标签例子          | 应用           |
| ------------ | ----------------- | -------------- |
| NER 命名实体 | PER/LOC/ORG       | 知识图谱、搜索 |
| 分词         | B-W/I-W/O         | 中文处理第一步 |
| 词性标注 POS | 名词/动词/形容词… | 句法分析的地基 |
| 关键词抽取   | B-KW/I-KW         | 摘要、索引     |
| 医疗实体     | 疾病/症状/药物    | 病历结构化     |

**学会一次 BIO + 一个预训练底座，整个家族全部解锁**——这是 NLP 里性价比最高的技能投资之一。

## 自测一下

> [!question]- 1. 为什么「北京」「大学」两个字不能各自独立分类？这个困难叫什么？
> 因为实体是**多字组合**，「北京」单独可能是城市名也可能是人名的一部分（如「王北京」），脱离组合无法判定。
> 这个困难叫**边界判定（boundary detection）**，与**类型判定**并称 NER 两大核心难题。BIO 用 B/I 记号把边界显式编码进标签空间，让模型可以端到端地同时学两件事——这是它优于「先切词再逐词分类」流水线方案的根本原因。

> [!question]- 2. 本课规则实验输出了『在清华大学』这样的脏边界。给出两条改进方向，一条不离开规则法，一条转向模型法。
> 规则法内改进：**前后缀配对 + 停用词修剪**——维护常见动词/介词前缀表（在/于/进了/加入），命中即回退修剪边界；或改用「最长匹配优先」的全词表匹配替代后缀猜测。
> 模型法：上 **BERT+CRF 序列标注器**——用几千条人工标注教模型从上下文学边界，泛化到没见过的机构名（规则法永远做不到这一点）。
> 工程真相：两者常被组合使用——模型主判 + 词典强校准。

> [!question]- 3. 「苹果发布了新 iPhone」和「我吃了个苹果」，静态词向量和 BERT 分别会怎么标注「苹果」？
> 静态词向量：两个「苹果」向量完全相同（NLP2 的天花板），下游分类器只能靠周围词的拼接特征硬猜，容易翻车。
> BERT：注意力机制让「苹果」的表示被上下文重塑——前一例被拉向「科技公司」语义区（邻居：发布/iPhone），后一例拉向「水果」（邻居：吃了）。标注头看到的已是消歧后的特征，准确率高得多。
> 这是「上下文相关表示」价值的最直观案例，NLP2 概念 5 预言在此兑现。

> [!question]- 4. 医院要把病历里的「疾病、症状、药物」三类实体抽出来建数据库，但只有预算标 2000 条句子。设计你的技术方案与评估重点。
> 方案：① 选中文医疗领域的公开预训练模型（如有领域版优先）；② 制定细标注规范（实体边界争议案例写进文档统一口径——规范质量决定上限）；③ 2000 条按 8:1:1 切分，BERT+CRF 训练；④ 评估重点：**按类别分开看 F1**（药物名通常最好学，症状描述最模糊），特别关注**边界精确率**（病历容不得把「急性阑尾炎术后」整段当疾病）；⑤ 上线后低置信样本回流标注迭代。
> 关键意识：医疗场景错抽的代价不对称——漏掉疾病比多抽一个无害词危险得多，阈值应向高召回倾斜（ML9 的代价权衡思想迁移）。
