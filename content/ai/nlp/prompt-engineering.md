## 生活场景切入

同一个模型，两个人用出天壤之别：

```text
用户 A：「帮我写个请假条」
  → 输出一篇通用范文，可能不合你的公司格式

用户 B：「你是我的助理。我明天请病假（感冒），给王经理写一条
        微信消息：50 字以内、口语化、提到会把工作交接给小李。」
  → 直接可用的成品
```

差距不在模型，在**提示词**。提示词工程（Prompt Engineering）听起来像玄学，实际是 DL7 讲的 in-context learning 的应用学：**模型的参数已经冻结，你能改变的只有输入——而输入的质量直接决定输出质量**。

## 核心概念拆解

### 概念 1：第一原则 —— 模型不是读心者

最常见的失败原因不是模型笨，而是任务描述太模糊。模型只能基于你给的信息做条件概率最大的续写：

```text
「写个请假条」的条件分布 → 千万人写过千万种请假条 → 输出最泛化的那种
加上格式/长度/收件人/事由约束后 → 条件分布急剧收窄 → 直击你要的那一种
```

**每个你没写的细节，模型都会替你随机决定一个默认值。**提示词工程的第一功课是把脑内的隐含期望显式化。

### 概念 2：五大技巧与它们的原理

**① 清晰指令 + 具体约束**

```text
差：总结这篇文章
好：用三个要点总结这篇文章，每点不超过 30 字，面向没读过原文的读者
```

原理：输出格式被收窄，评估标准被外置。

**② 角色设定（System Prompt / Persona）**

```text
「你是一位资深儿科医生，用家长能听懂的语言回答」
```

原理：角色词激活参数中对应的语域与知识分布——「资深医生」和「小学生」作为前缀会把后续文本引向完全不同的统计区域（NLP7 条件概率的直接应用）。

**③ Few-shot 示例**

```text
把下列评论分类为 正/负：
评论：太好看了 → 正
评论：浪费钱 → 负
评论：值回票价 → ?
```

原理：DL7 的 ICL 本尊——示例就是上下文中的临时训练数据，模型现场提取分类模式。经验上示例的**多样性**比数量更重要（覆盖边界情形）。

**④ 思维链 Chain-of-Thought（CoT）**

```text
差：小明有 23 个苹果，买了 3 箱每箱 8 个，送人 15 个，还剩几个？直接给答案。
好：……请一步步推理再给出最终答案。
```

原理：自回归模型每一步的计算预算有限，「直接给答案」逼它在单步内完成全部运算；要求写出中间步骤，等于把复杂计算拆成多个简单步骤接力——每步只需局部正确。实测在算术与逻辑类任务上提升显著（GPT-3.5 之后甚至无需示例，零样本 CoT 的「Let's think step by step」即可生效）。

**⑤ 结构化输出**

```text
请按以下 JSON 格式输出：
{"情绪": "正/负", "置信度": 0~1, "关键词": ["…"]}
```

原理：结构即契约——下游程序可以直接解析；同时迫使模型先内部分类再表态，减少含混其辞。

### 概念 3：迭代心态 —— 提示词也是要调试的

专业玩家对待 prompt 的方式与工程师对待代码一致：

```text
① 建立测试集：攒 10~20 个代表性输入 + 期望输出
② 改一版 prompt → 全量跑一遍测试集 → 数对错
③ 针对错误案例分析失败模式 → 定向修改措辞/增删示例
④ 循环直到指标稳定，锁定版本
```

这与 ML9 的评估纪律同构：**没有测试集的 prompt 优化都是凭感觉**。模型升级时重跑测试集还能立刻发现行为变化——prompt 是需要维护的资产，不是一次性的咒语。

### 概念 4：反面教材 —— 浪费 token 的写法

| 反模式                 | 问题                       | 改法                         |
| ---------------------- | -------------------------- | ---------------------------- |
| 「请你一定要好好写」   | 情绪施压无信息量           | 写清楚具体标准               |
| 一段话塞十个不相关需求 | 注意力稀释，各任务都做不好 | 拆分成多轮对话/多次调用      |
| 关键约束埋在段落中间   | 容易被忽略                 | 重要约束放开头或结尾+编号    |
| 让模型猜输出格式       | 每次格式漂移               | 给模板或 few-shot 样例       |
| 超长上下文堆料不筛选   | 干扰信号+成本飙升          | 只放相关材料（GenAI RAG 见） |

### 概念 5：边界 —— 提示词不是银弹

保持清醒的三条边界：

1. **知识缺失救不了**：模型不知道你们公司的内部制度，写得再好的提示也无法凭空变出信息（解药是 RAG，GenAI 板块讲）
2. **能力不足绕不开**：复杂推理的硬上限由模型本身决定，CoT 只是释放已有潜力
3. **可靠性有极限**：关键决策场景必须保留人工复核，幻觉问题没有纯提示词解法（GenAI 安全课正面处理）

提示词工程的定位一句话：**它是人与冻结参数之间最高效的通信协议设计学，而不是魔法**。

## 自测一下

> [!question]- 1. 为什么「角色设定」能改变输出风格？用 NLP 学过的概念解释其机制。
> 语言模型本质是条件概率机 P(下一词|前文)。前缀「你是资深儿科医生」使后续每个词的采样都发生在「医疗问答语域」的条件分布下——术语选择、句式礼貌度、知识范围全部被这个条件重塑。
> 这正是 NLP7 temperature 一节说的「条件分布收窄」的角色版：角色词是最廉价却最有效的条件注入方式之一。

> [!question]- 2. CoT 对什么类型的任务无效甚至有害？说明理由。
> 两类场景慎用：① **感知/直觉型任务**（情感判断、风格识别）——人类专家本就一步到位，强制展开步骤反而引入冗余中间错误；② **简单任务**——「1+1 等于几？请一步步推理」纯属浪费 token 与延迟。
> 另外注意：CoT 展示的推理过程并不总是模型真实的内部计算路径（研究显示存在「事后合理化」现象）——它的价值在于提升答案准确率，不能当作模型思维的可信透镜。

> [!question]- 3. 你的 few-shot 分类器在某类边缘案例上总出错。给出三条改进方向。
> ① **补充针对性示例**：在提示里加入 1~2 条该边缘类型的最具代表性错例及其正确标签（覆盖盲区的最直接手段）；② **调整示例顺序与描述**——把最难区分的两个类的对照示例相邻摆放，并在指令中显式写出两者的判别要点；③ **升级方案**——若类别体系复杂、样本充足（数百条），few-shot 的天花板到了，改用 BERT 微调（NLP6 方案）或大模型微调（DL10）。
> 判断何时放弃 prompt 转向微调本身就是重要的工程判断：**ICL 适合快速验证与轻量任务，稳定量产的高精度需求属于微调**。

> [!question]- 4. 同事说「我把公司产品手册整份贴进提示词，让模型答客户问题」。指出这个方案的三个问题并预告正确架构。
> 问题：① **token 成本爆炸**——每次提问都携带全手册，费用随手册长度线性增长；② **注意力稀释**——超长无关内容会降低模型对关键段落的利用精度（大海捞针实验证明长上下文中部信息利用率下降）；③ **无法扩展**——手册更新需改所有调用，多文档场景直接崩溃。
> 正确架构是 **RAG（检索增强生成）**：先把手册切片建向量索引，用户提问时只检索最相关的几段塞进提示词。这是 GenAI 板块的核心课题——本课的「token 是稀缺资源」意识正是理解 RAG 必要性的前置知识。
